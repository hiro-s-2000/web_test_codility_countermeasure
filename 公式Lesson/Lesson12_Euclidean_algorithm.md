## ChocolatesByNumbers（Easy）

> 公式の問題文: [ChocolatesByNumbers](https://app.codility.com/programmers/lessons/12-euclidean_algorithm/chocolates_by_numbers/)

### 問題の要約

- 円形に並んだ `N` 個のチョコレートに 0〜N−1 の番号が付いている。
- 0番から食べ始め、`X` を食べたら次は `(X + M) mod N` 番に進む。
- すでに食べた番号（包み紙だけ）に着いたら止まる。食べた個数を返す。
- `N`、`M` はどちらも 1〜1,000,000,000。

| 入力 | 答え | 一言 |
|---|---|---|
| N=10, M=4 | 5 | 0, 4, 8, 2, 6 と食べて 0 に戻る |

### 解答コード（最大公約数 O(log(N+M))）

```kotlin
fun solution(N: Int, M: Int): Int {
    // ユークリッドの互除法で gcd(N, M) を求める
    var a = N
    var b = M
    while (b != 0) {
        val t = a % b
        a = b
        b = t
    }
    // 食べる個数は N / gcd(N, M)
    return N / a
}
```

### 考え方とポイント

- 0 から M ずつ進んで初めて 0 に戻るのは、進んだ距離が N と M の最小公倍数になった時なので、答えは lcm(N, M) / M = N / gcd(N, M) だ。
- 0 以外の番号で止まることはない（最初に重なるのは必ず 0 番）。だから「0 に戻るまでの歩数」を数えればよい。
- gcd はユークリッドの互除法 `gcd(a, b) = gcd(b, a % b)` で求める。
- 計算量は時間 O(log(N+M))、追加メモリ O(1)。

### 試験で間違えやすい点

- 1 個ずつ歩いて数えるシミュレーションは、N=10^9 で配列も時間も足りない。
- lcm を `N * M / gcd` で作ると Int で溢れる（最大 10^18）。lcm を経由せず `N / gcd` と直接割る。
- M が N より大きくても互除法はそのまま動く（1回目で a と b が入れ替わる）。

|---|---|---|

| N=10, M=10 | 1 | M が N の倍数ならすぐ 0 に戻る |
| N=10, M=3 | 10 | 互いに素なら全部食べる |
| N=6, M=15 | 2 | M が N より大きい |

## CommonPrimeDivisors（Medium）

> 公式の問題文: [CommonPrimeDivisors](https://app.codility.com/programmers/lessons/12-euclidean_algorithm/common_prime_divisors/)

### 問題の要約

- 同じ長さ Z の整数配列 `A` と `B` が渡される。Z は 1〜100,000、各要素は 1〜2,147,483,647。
- 位置 K ごとに、`A[K]` と `B[K]` の「素因数の集合」（何回掛かるかは無視）がまったく同じかを調べる。
- 同じだった位置の個数を返す。
- 1 は素因数を持たないので、`1` と `1` は「どちらも空集合」で一致になる。

| A[K] と B[K] | 素因数 | 一致？ |
|---|---|---|
| 15 と 75 | {3, 5} と {3, 5} | 一致 |
| 10 と 30 | {2, 5} と {2, 3, 5} | 不一致 |
| 9 と 5 | {3} と {5} | 不一致 |
| A=[15,10,3], B=[75,30,5] | (15,75)一致、(10,30)不一致、(3,5)不一致 | 答えは 1 |

### 解答コード（最大公約数で割り切る）

```kotlin
fun solution(A: IntArray, B: IntArray): Int {
    var count = 0
    for (k in A.indices) {
        val g = gcd(A[k], B[k])
        // g の素因数だけで割り切れれば、それ以外の素因数はない
        if (onlyPrimesOf(A[k], g) && onlyPrimesOf(B[k], g)) count++
    }
    return count
}

fun gcd(a: Int, b: Int): Int = if (b == 0) a else gcd(b, a % b)

// x の素因数がすべて g の素因数に含まれるか
fun onlyPrimesOf(x: Int, g: Int): Boolean {
    var n = x
    var d = gcd(n, g)
    while (d != 1) {
        n /= d
        d = gcd(n, g)
    }
    return n == 1
}
```

### 考え方とポイント

- 2つの数の素因数の集合が同じ ⇔ どちらも「最大公約数 g の素因数だけでできている」。素因数分解はしない。
- `A[k]` から `gcd(A[k], g)` を割り続け、共通部分がなくなった時に 1 になっていれば、`A[k]` の素因数はすべて g にある。`B[k]` も同じように調べる。
- g は両方の約数なので、g の素因数は両方に必ずある。だから両方が上の条件を満たせば集合は完全に一致する。
- 素因数分解を √N（約46,000）まで試し割りすると 100,000 組では遅すぎる。gcd なら 1回 O(log N) で済む。
- 計算量は 1組あたり O(log² M)（M は値の最大）、全体で O(Z · log² M)。追加メモリは O(1)。

### 試験で間違えやすい点

- 割り続ける相手を `gcd(n, g)` で毎回取り直す。最初の `gcd(A[k], g)` で1回割っただけでは、`A[k]=8, g=2` のように同じ素因数が何回も掛かる数を取り逃す。
- `1` と `1` は一致（どちらも素因数なし）。`1` と `2` は不一致。g=1 のときは、両方が 1 の時だけ一致になる。
- 値は Int の上限まで来るが、割り算と剰余しか使わないので溢れない。掛け算（例: `a * b / gcd` で最小公倍数）を持ち込むと溢れる。
