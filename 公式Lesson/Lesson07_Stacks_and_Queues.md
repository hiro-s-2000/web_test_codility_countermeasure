## Brackets（Easy）

> 公式の問題文: [Brackets](https://app.codility.com/programmers/lessons/7-stacks_and_queues/brackets/)

### 問題の要約

- 文字列 `S`（長さ N は 0〜200,000）が渡される。文字は `(` `)` `[` `]` `{` `}` の6種類だけ。
- 括弧が正しく入れ子になっていれば 1、なっていなければ 0 を返す。
- 空文字列は「正しい」とみなす（1を返す）。
- 「正しい」とは、開き括弧と閉じ括弧の種類が対応し、交差せずに閉じていること。

| 入力 | 答え | 一言 |
|---|---|---|
| `"{[()()]}"` | 1 | 正しく入れ子になっている |
| `"([)()]"` | 0 | `(` の中で `]` が先に閉じて交差している |

### 解答コード（スタック O(N)）

```kotlin
fun solution(S: String): Int {
    // 開き括弧を積むスタック（配列と添字で代用）
    val st = CharArray(S.length)
    var top = 0
    for (c in S) {
        when (c) {
            '(', '[', '{' -> st[top++] = c
            else -> {
                if (top == 0) return 0
                val open = st[--top]
                if (c == ')' && open != '(') return 0
                if (c == ']' && open != '[') return 0
                if (c == '}' && open != '{') return 0
            }
        }
    }
    // 開いたまま残っていたら不正
    return if (top == 0) 1 else 0
}
```

### 解答コード（別解：ArrayDeque）

```kotlin
fun solution(S: String): Int {
    val pair = mapOf(')' to '(', ']' to '[', '}' to '{')
    val st = ArrayDeque<Char>()
    for (c in S) {
        if (c !in pair) st.addLast(c)
        else if (st.isEmpty() || st.removeLast() != pair[c]) return 0
    }
    return if (st.isEmpty()) 1 else 0
}
```

### 考え方とポイント

- 開き括弧はスタックに積み、閉じ括弧が来たら一番上を取り出して種類が対応するか確かめる。
- 一番最近に開いた括弧から先に閉じる必要があるので、「後入れ先出し」のスタックがぴったり合う。
- 最後にスタックが空なら 1。開いたまま残っていれば 0。
- 計算量は時間 O(N)、追加メモリは O(N)（全部が開き括弧のとき）。

### 試験で間違えやすい点

- 閉じ括弧が来たときにスタックが空かどうかを先に確かめる。`")"` のような入力で空のスタックから取り出して落ちる。
- 最後の「スタックが空か」の確認を忘れると、`"(("` で 1 を返してしまう。
- 空文字列は 1。ループが1回も回らず、スタックも空なので自然に 1 になる。
- Kotlin の `ArrayDeque` は `kotlin.collections` のものが import なしで使える。`java.util.Stack` より速い。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| `""` | 1 | 空文字列 |
| `")"` | 0 | いきなり閉じる（空のスタック） |
| `"(("` | 0 | 開いたまま終わる |
| `"([]{})"` | 1 | 種類が混ざった正しい形 |
| `"(]"` | 0 | 種類が違う |
| `"()()"` | 1 | 並べた形（VW） |
| `"(" × 100000 + ")" × 100000` | 1 | 最大の深さ |

## Fish（Easy）

> 公式の問題文: [Fish](https://app.codility.com/programmers/lessons/7-stacks_and_queues/fish/)

### 問題の要約

- 川に `N` 匹（1〜100,000）の魚が上流から順に並んでいる。番号が小さいほど上流側。
- `A[i]` は魚の大きさ（0〜1,000,000,000、全部ちがう値）、`B[i]` は向き（0 = 上流へ、1 = 下流へ）。
- 下流へ向かう魚の後ろ（下流側）に上流へ向かう魚がいて、間に生きた魚がいなければ出会う。大きい方が小さい方を食べ、向きはそのまま。
- 同じ向きの魚どうし、また「上流向きが前、下流向きが後ろ」の組は出会わない。
- 最後まで生き残る魚の数を返す。

| A | B | 答え | 一言 |
|---|---|---|---|
| `[4, 3, 2, 1, 5]` | `[0, 1, 0, 0, 0]` | 2 | 3が2と1を食べ、5に食べられる。0番と4番が残る |

### 解答コード（スタック O(N)）

```kotlin
fun solution(A: IntArray, B: IntArray): Int {
    // 下流へ向かっていて、まだ生きている魚の大きさを積む
    val down = IntArray(A.size)
    var top = 0
    var upAlive = 0 // 上流へ逃げ切った魚の数
    for (i in A.indices) {
        if (B[i] == 1) {
            down[top++] = A[i]
        } else {
            // 上流向きの魚が、待ち構える下流向きの魚を食べていく
            while (top > 0 && down[top - 1] < A[i]) top--
            if (top == 0) upAlive++
        }
    }
    return upAlive + top
}
```

### 考え方とポイント

- 上流から1匹ずつ見て、下流向きの魚をスタックに積み、上流向きの魚が来たらスタックの上から戦わせる。
- 上流向きの魚は、直前の下流向きの魚（スタックの一番上）から順に出会う。自分より小さければ食べて `top--`、大きければ自分が食べられて終わり。
- スタックが空になるまで食べ切った上流向きの魚は、もう誰にも出会わないので生き残りとして数える。
- 最後にスタックに残った下流向きの魚も、後ろに上流向きの魚がもういないので全員生き残る。答えは `upAlive + top`。
- 各魚はスタックに1回積まれ、1回しか降ろされないので、時間 O(N)、追加メモリ O(N)。

### 試験で間違えやすい点

- 出会うのは「下流向き（1）が上流側、上流向き（0）が下流側」の組だけ。`B` の 0 と 1 の意味を逆に覚えると全部ずれる。
- 上流向きの魚が食べられたときに `upAlive` を数えないこと。`top == 0` になったときだけ数える。
- 一番上流にいる上流向きの魚や、スタックが空の時に来た上流向きの魚は、戦わずにそのまま生き残る。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| A=`[1]`, B=`[0]` | 1 | N=1 |
| A=`[1, 2]`, B=`[1, 0]` | 1 | 出会って上流向きが勝つ |
| A=`[1, 2]`, B=`[0, 1]` | 2 | 背中合わせは出会わない |
| A=`[5, 1, 2, 3]`, B=`[1, 1, 1, 0]` | 1 | 2匹食べた後に食べられる |
| A=`[2, 1, 3, 4]`, B=`[1, 1, 0, 0]` | 2 | 下流向きを全部食べて逃げ切る |
| A=`[1, 2, 3, 4, 5]`, B=`[1, 1, 1, 1, 1]` | 5 | 全員同じ向き |
| A=`[1000000000, 0]`, B=`[1, 0]` | 1 | 最大値と0 |

## Nesting（Easy）

> 公式の問題文: [Nesting](https://app.codility.com/programmers/lessons/7-stacks_and_queues/nesting/)

### 問題の要約

- `(` と `)` だけでできた文字列 `S` が渡される。長さ `N` は0〜1,000,000。
- 括弧の対応が正しく取れていれば1、取れていなければ0を返す。
- 空文字列は「正しい」とみなす（1を返す）。
- 括弧は1種類だけなので、種類の食い違いは起きない。

| S | 答え | 一言 |
|---|---|---|
| `(()(())())` | 1 | 入れ子と並びが混ざっても正しい |
| `())` | 0 | 閉じ括弧が1つ多い |

### 解答コード（カウンタで O(N)）

```kotlin
fun solution(S: String): Int {
    var depth = 0 // まだ閉じていない '(' の数
    for (c in S) {
        if (c == '(') {
            depth++
        } else {
            depth--
            // 開いていないのに閉じた時点でアウト
            if (depth < 0) return 0
        }
    }
    // 最後に全部閉じていれば正しい
    return if (depth == 0) 1 else 0
}
```

### 考え方とポイント

- 括弧が1種類なので、スタックの中身は全部 `(` になる。だからスタックの代わりに「開いている数」を数えるだけでよい。
- `(` で +1、`)` で -1。途中で一度でも負になったら、対応する `(` がない `)` があるので0。
- 最後まで読んで0に戻っていれば1。正のまま終わったら閉じ忘れなので0。
- 計算量は時間 O(N)、追加メモリ O(1)。

### 試験で間違えやすい点

- 最後の `depth == 0` だけを見ると、`)(` を正しいと判定してしまう。途中で負になったら即座に0を返す。
- 逆に途中の判定だけで最後を見ないと、`((` を正しいと判定してしまう。
- 空文字列（N = 0）は1。ループが回らず `depth == 0` になるので、特別扱いは不要。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| `""`（空） | 1 | N = 0 |
| `(` | 0 | 閉じ忘れ |
| `)(` | 0 | 個数は合っても順番が逆 |
| `()()` | 1 | 並べた形 |
| `(()` | 0 | 最後に1つ残る |
| `(` を500,000個 + `)` を500,000個 | 1 | 最大サイズ・最大の深さ |

## StoneWall（Easy）

> 公式の問題文: [StoneWall](https://app.codility.com/programmers/lessons/7-stacks_and_queues/stone_wall/)

### 問題の要約

- 長さ N メートルの石壁を作る。`H[i]` は i メートル目から i+1 メートル目までの壁の高さ。
- 壁は直方体の石ブロックを積んで作る。ブロックの数をできるだけ少なくしたい。
- 必要なブロックの最小個数を返す。
- N は 1〜100,000、`H[i]` は 1〜1,000,000,000 の整数。

| H | 答え | 一言 |
|---|---|---|
| [8, 8, 5, 7, 9, 8, 7, 4, 8] | 7 | 公式の例 |

### 解答コード（スタック O(N)）

```kotlin
fun solution(H: IntArray): Int {
    // 今「使いかけ」のブロックの高さを下から順に積む
    val stack = IntArray(H.size)
    var top = 0
    var count = 0
    for (h in H) {
        // 今の高さより高いブロックはここで終わる
        while (top > 0 && stack[top - 1] > h) top--
        // 同じ高さのブロックがあれば、それを横に伸ばすだけ
        if (top > 0 && stack[top - 1] == h) continue
        // なければ新しいブロックを置く
        stack[top++] = h
        count++
    }
    return count
}
```

### 考え方とポイント

- 左から見ていき、「まだ右へ伸ばせるブロックの高さ」をスタックに持つ。スタックは下ほど低い。
- 今の高さ `h` より高いブロックは、ここで途切れるので pop する。
- pop した後、一番上が `h` と同じなら、そのブロックを右へ伸ばせば済むので数えない。違えば新しいブロックを置いて数える。
- 各高さは1回 push、最大1回 pop なので、計算量は O(N)、追加メモリは O(N)。

### 試験で間違えやすい点

- 低いところで高いブロックを pop し忘れると、`[1, 2, 1]` を3と数えてしまう（正しくは2。上に残った高さ2を消さないと、下の高さ1のブロックを伸ばせない）。
- pop の条件は `>`。`>=` にすると同じ高さのブロックまで消え、`[5, 5, 5]` を3と数える。
- `ArrayDeque` でもよいが、`IntArray` と添字で持つほうが速く、`removeLast()` などの API の違いでも迷わない。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| [1] | 1 | 最小のN |
| [5, 5, 5] | 1 | 全部同じ高さは1個 |
| [1, 2, 3] | 3 | 上り坂は上に積み足す |
| [3, 2, 1] | 3 | 下り坂は毎回新しいブロック |
| [2, 1, 2] | 3 | 間が低いとブロックが途切れる |
| [1, 2, 1] | 2 | 下の段のブロックは伸ばせる |
| [8, 8, 5, 7, 9, 8, 7, 4, 8] | 7 | 公式の例 |
