## FrogJmp（Easy）

> 公式の問題文: [FrogJmp](https://app.codility.com/programmers/lessons/3-time_complexity/frog_jmp/)

### 問題の要約

- カエルが位置 `X` にいて、位置 `Y` 以上のどこかに行きたい。
- 1回のジャンプでちょうど `D` だけ進む。
- `Y` 以上に届くまでの最小のジャンプ回数を返す。
- `X`、`Y`、`D` はどれも 1〜1,000,000,000 の整数で、`X ≤ Y`。

| 入力 | 答え | 一言 |
|---|---|---|
| X=10, Y=85, D=30 | 3 | 40 → 70 → 100 で85を越える |

### 解答コード（O(1) 割り算）

```kotlin
fun solution(X: Int, Y: Int, D: Int): Int {
    val dist = Y - X
    // 割り切れなければ、もう1回跳ぶ（切り上げ）
    return dist / D + if (dist % D == 0) 0 else 1
}
```

### 考え方とポイント

- 進む距離 `Y - X` を `D` で割って切り上げれば、それが最小回数だ。
- `dist / D` は切り捨てなので、余りが出たら1を足す。
- ループで1回ずつ跳ぶと、`D=1`・距離10億で10億回回って時間切れになる。
- 計算量は時間 O(1)、追加メモリ O(1)。

### 試験で間違えやすい点

- `X == Y` のときは1回も跳ばないので0。`(dist + D - 1) / D` でも0になるが、「最低1回」と思い込まない。
- 切り上げを `(dist + D - 1) / D` と書くと途中が最大で約20億になる。この制約では Int に収まるが、上限ぎりぎりなので余りで判定する書き方のほうが安全だ。
- `Math.ceil((dist / D).toDouble())` のように割った後で Double にすると、先に整数の割り算で切り捨てられて切り上げにならない（`Math.ceil(dist / D)` は、Kotlin ではそもそも型エラーでコンパイルできない）。Double を使うなら `ceil(dist.toDouble() / D)` だが、整数だけで書くほうが安全だ。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| X=10, Y=85, D=30 | 3 | 公式の例 |
| X=5, Y=5, D=7 | 0 | 最初から届いている |
| X=10, Y=70, D=30 | 2 | 割り切れる（ちょうど着地） |
| X=1, Y=2, D=1000000000 | 1 | 1回で大きく越える |
| X=1, Y=1000000000, D=1 | 999999999 | 最大の回数 |
| X=1, Y=1000000000, D=1000000000 | 1 | 大きい値どうし |

## PermMissingElem（Easy）

> 公式の問題文: [PermMissingElem](https://app.codility.com/programmers/lessons/3-time_complexity/perm_missing_elem/)

### 問題の要約

- 長さ `N`（0〜100,000）の配列 `A` が渡される。要素はすべて異なる。
- 各要素は 1〜N+1 の範囲にある。N+1 種類の値のうち、ちょうど1つだけが配列にない。
- その欠けている値を返す。
- `N = 0`（空配列）もありうる。そのときは 1 が欠けている。

| 入力 | 答え | 一言 |
|---|---|---|
| `[2, 3, 1, 5]` | 4 | 1〜5 のうち 4 がない |

### 解答コード（合計の差・O(N)）

```kotlin
fun solution(A: IntArray): Int {
    val n = A.size.toLong() + 1
    // 1〜N+1 の合計。最大で約50億なので Long で計算する
    val total = n * (n + 1) / 2
    var sum = 0L
    for (x in A) sum += x
    return (total - sum).toInt()
}
```

### 解答コード（別解：XOR）

```kotlin
fun solution(A: IntArray): Int {
    // 同じ値どうしの XOR は 0 になるので、ペアにならない値だけが残る
    var x = A.size + 1
    for (i in A.indices) {
        x = x xor (i + 1) xor A[i]
    }
    return x
}
```

### 考え方とポイント

- 「1〜N+1 の合計」から「配列の合計」を引けば、欠けている値が残る。
- 1〜M の合計は `M * (M + 1) / 2` で、ループなしで出せる。
- 並べ替え（O(N log N)）や、値ごとに配列を探す O(N²) は不要。1回なめるだけでよい。
- 別解の XOR は、1〜N+1 と配列の要素をすべて XOR すると、2回出た値は消えて欠けた値だけが残る性質を使う。溢れの心配がない。
- 計算量は時間 O(N)、追加メモリ O(1)。

### 試験で間違えやすい点

- 合計を `Int` で計算すると溢れる。N = 100,000 のとき 1〜100,001 の合計は 5,000,150,001 で、Int の上限（約21億）を超える。`total` も `sum` も `Long` にする。
- `n * (n + 1) / 2` の `n` が `Int` のままだと、掛け算の時点で溢れる。先に `toLong()` しておく。
- 空配列（N = 0）を忘れない。答えは 1。上の式なら `n = 1` で `total = 1`、`sum = 0` となり、そのまま 1 が返る。
- 欠けているのは「最後の値 N+1」のこともある。`A.size` までしか見ない書き方だと取りこぼす。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| `[]` | 1 | 空配列 |
| `[1]` | 2 | 欠けているのが最後の値 |
| `[2]` | 1 | 欠けているのが最初の値 |
| `[2, 3, 4]` | 1 | 1 がない |
| `[1, 2, 3]` | 4 | N+1 がない |
| `[2, 3, …, 100001]`（N = 100,000） | 1 | 最大サイズで合計が Int を超える |

## TapeEquilibrium（Easy）

> 公式の問題文: [TapeEquilibrium](https://app.codility.com/programmers/lessons/3-time_complexity/tape_equilibrium/)

### 問題の要約

- 空でない整数の配列 `A`（長さ N は 2〜100,000、要素は -1,000〜1,000）が渡される。
- 位置 `P`（1 ≦ P ≦ N-1）で配列を前半 `A[0..P-1]` と後半 `A[P..N-1]` の2つに切る。どちらも1要素以上になる。
- 切り方ごとに「前半の和 − 後半の和」の絶対値を求め、その最小値を返す。

| 入力 | 答え | 一言 |
|---|---|---|
| `[3, 1, 2, 4, 3]` | 1 | P=3 で前半6・後半7、差は1 |

### 解答コード（O(N)：全体の和から前半の和を引く）

```kotlin
import kotlin.math.abs

fun solution(A: IntArray): Int {
    val total = A.sum()
    var left = 0
    var best = Int.MAX_VALUE
    // P は 1..N-1。最後の要素は必ず後半に残す
    for (i in 0 until A.size - 1) {
        left += A[i]
        val right = total - left
        val diff = abs(left - right)
        if (diff < best) best = diff
    }
    return best
}
```

### 考え方とポイント

- 後半の和は「全体の和 − 前半の和」で出せるので、前半の和を1つずつ足しながら全部の切り方を1回で調べる。
- 切り方ごとに和を数え直すと O(N²) になり、N=100,000 では性能テストで落ちる。
- 和の最大は 100,000 × 1,000 = 1億なので、この問題は Int で溢れない。
- 計算量は時間 O(N)、追加メモリ O(1)。

### 試験で間違えやすい点

- ループを `A.indices` まで回すと P=N（後半が空）も数えてしまう。`0 until A.size - 1` で最後の要素は後半に残す。
- `best` の初期値を 0 にすると常に 0 が返る。`Int.MAX_VALUE` など十分大きい値から始める。
- 要素に負の数があるので、差は必ず `abs` を取る。前半と後半の大小は決め打ちできない。

| `[1, 2]` | 1 | 最小の N（切り方は1通り） |

| `[-10, -20, -30, -40]` | 20 | 全部負の数 |
