# Lesson 9 Maximum slice problem（公式のlessonの問題）

> Codility公式の [Lesson 9: Maximum slice problem](https://app.codility.com/programmers/lessons/9-maximum_slice_problem/) の全問題を、Kotlinで解いた解答です。このLessonの問題は **MaxProfit**、**MaxSliceSum**、**MaxDoubleSliceSum** の3問です。
> 問題文は公式ページで読み、下の要約は確認用に使ってください。先に自分で解いてから、答え合わせに解答を開くのがおすすめです。

## MaxProfit（Easy）

> 公式の問題文: [MaxProfit](https://app.codility.com/programmers/lessons/9-maximum_slice_problem/max_profit/)

### 問題の要約

- 配列 `A` は、ある株の `N` 日間の毎日の株価。`N` は 0〜400,000、各値は 0〜200,000。
- ある日 P に買って、同じ日か後の日 Q（P ≤ Q）に売ると、利益は `A[Q] - A[P]`。
- 1回だけ売買したときの最大の利益を返す。利益が出ない（どの組でも0以下）なら0を返す。
- `N` が0や1のときも0を返す。

| 入力 | 答え | 一言 |
|---|---|---|
| `[23171, 21011, 21123, 21366, 21013, 21367]` | 356 | 1日目（21011）に買い、5日目（21367）に売る |

### 解答コード（O(N)・それまでの最安値を覚える）

```kotlin
fun solution(A: IntArray): Int {
    if (A.isEmpty()) return 0
    var minPrice = A[0]  // 今日までの最安値
    var best = 0         // 利益が出なければ0のまま
    for (p in A) {
        // 今日売るなら、それまでの最安値で買ったのが一番得
        if (p - minPrice > best) best = p - minPrice
        if (p < minPrice) minPrice = p
    }
    return best
}
```

### 解答コード（別解：前日との差に最大部分和）

```kotlin
fun solution(A: IntArray): Int {
    // 前日との差 A[i]-A[i-1] を並べると、利益は差の連続区間の和になる
    var endHere = 0  // 今日で終わる区間の最大和（負になったら0から始め直す）
    var best = 0
    for (i in 1 until A.size) {
        endHere = maxOf(0, endHere + A[i] - A[i - 1])
        best = maxOf(best, endHere)
    }
    return best
}
```

### 考え方とポイント

- 「売る日」を左から順に決めていき、その日までの最安値で買ったと考えれば、1回の走査で最大の利益が出る。
- 全部の組 (P, Q) を試すと O(N²) で、N = 400,000 では間に合わない。
- 別解は Lesson 9 の主題の「最大部分和（Kadane法）」。`A[Q] - A[P]` は前日との差を P+1〜Q 日分足したものに等しいので、差の配列の最大部分和が答えになる。
- 最安値の更新は、利益を計算した後でも前でもよい（同じ日に売買すると利益0なので結果は変わらない）。
- 計算量は時間 O(N)、追加メモリ O(1)。

### 試験で間違えやすい点

- 空配列で `A[0]` を読むと例外になる。`N` は0もあり得るので、先に `isEmpty()` を確かめる（別解は `1 until 0` が空ループなのでそのまま0を返す）。
- 下がり続ける株価で負の値を返さない。`best` を0から始めれば、損になる売買は選ばれない。
- 最大値−最小値ではない。最小値が最大値より後の日にあると、その組では売買できない（例: `[2, 10, 1, 5]` は8であって9ではない）。
- 値は 0〜200,000 なので差は Int に収まり、Long は要らない。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| `[]` | 0 | 空配列 |
| `[5]` | 0 | 1日だけ |
| `[5, 4, 3, 2, 1]` | 0 | 下がり続けると0 |
| `[1, 2]` | 1 | 一番短い利益 |
| `[2, 10, 1, 5]` | 8 | 後に来る最安値では買えない |
| `[3, 1, 4, 1, 5]` | 4 | 最安値が2回出る |
| `[0, 200000]` | 200000 | 最大の差 |

## MaxSliceSum（Easy）

> 公式の問題文: [MaxSliceSum](https://app.codility.com/programmers/lessons/9-maximum_slice_problem/max_slice_sum/)

### 問題の要約

- 空でない整数配列 `A`（長さ N は 1〜1,000,000、各要素は −1,000,000〜1,000,000）が渡される。
- 連続した区間 `A[P..Q]`（0 ≤ P ≤ Q < N）を「スライス」と呼ぶ。スライスは1要素以上で、空にはできない。
- スライスの和の最大値を返す。
- 答えは Int の範囲に収まることが保証されている。

| A | 答え | 一言 |
|---|---|---|
| `[3, 2, -6, 4, 0]` | 5 | 先頭の `3, 2` が最大。`4, 0` は4止まり |

### 解答コード（O(N) カダネ法）

```kotlin
fun solution(A: IntArray): Int {
    var cur = 0L            // 今の位置で終わるスライスの最大和
    var best = Long.MIN_VALUE
    for (a in A) {
        // 前から続けるか、ここから始め直すか
        cur = maxOf(cur + a, a.toLong())
        if (cur > best) best = cur
    }
    return best.toInt()
}
```

### 考え方とポイント

- 「位置 i で終わるスライスの最大和」を左から順に更新し、その最大を答えにする（カダネ法）。
- 位置 i で終わる最大和は、`前の位置で終わる最大和 + A[i]` と `A[i]` だけ、の大きいほう。前の和がマイナスなら捨てて始め直す。
- スライスは空にできないので、`best` の初期値は0ではなく `Long.MIN_VALUE`（または `A[0]`）にする。
- 計算量は時間 O(N)、追加メモリ O(1)。

### 試験で間違えやすい点

- 全部が負の数のとき、答えは0ではなく一番大きい要素（例: `[-5, -2, -9]` は −2）。`best = 0` から始めたり、`cur` を `maxOf(0, cur + a)` で0に戻す書き方にしたりすると、0を返してしまう。
- 途中の和は Long にしておくと安心。答えは Int に収まるが、Long で数えて最後に `toInt()` すれば溢れを考えなくて済む。
- `maxOf(cur + a, a.toLong())` の `a` は Int なので、Long と比べるには `toLong()` が要る（`maxOf(Long, Int)` はコンパイルエラー）。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| `[-1000000]` | -1000000 | N=1、最小値 |
| `[-5, -2, -9]` | -2 | 全部負なら最大の要素 |
| `[0, 0, 0]` | 0 | 全部0 |
| `[5, -10, 6]` | 6 | マイナスが大きいと始め直す |
| `[2, -1, 2]` | 3 | 小さいマイナスは越えてつなぐ |
| `[-3, 4, -1, 2, -6, 1]` | 5 | 真ん中の区間が最大 |
| N=1,000,000、すべて −1,000,000 | -1000000 | 最大サイズで全部負 |

## MaxDoubleSliceSum（Medium）

> 公式の問題文: [MaxDoubleSliceSum](https://app.codility.com/programmers/lessons/9-maximum_slice_problem/max_double_slice_sum/)

### 問題の要約

- 長さ `N`（3〜100,000）の整数配列 `A` が渡される。要素は −10,000〜10,000。
- 添字の組 `(X, Y, Z)`（`0 ≤ X < Y < Z < N`）を「ダブルスライス」と呼ぶ。
- その和は、`A[X+1]` から `A[Z-1]` までの合計から `A[Y]` を除いたもの。両端 `A[X]`、`A[Z]` と真ん中 `A[Y]` は入らない。
- ダブルスライスの和の最大値を返す。
- `X+1 = Y = Z-1` なら和は0（何も足さない）なので、答えは必ず0以上になる。

| 入力 | 答え | 一言 |
|---|---|---|
| `[3, 2, 6, -1, 4, 5, -1, 2]` | 17 | (0, 3, 6) で 2+6+4+5。真ん中の −1 を飛ばす |

### 解答コード（左右から最大和を作る O(N)）

```kotlin
fun solution(A: IntArray): Int {
    val n = A.size
    // left[i]: i で終わる区間の最大和（空でもよいので0以上）
    val left = IntArray(n)
    for (i in 1 until n - 1) {
        left[i] = maxOf(0, left[i - 1] + A[i])
    }
    // right[i]: i から始まる区間の最大和（空でもよい）
    val right = IntArray(n)
    for (i in n - 2 downTo 1) {
        right[i] = maxOf(0, right[i + 1] + A[i])
    }
    var best = 0
    // 真ん中 Y を全部試す。Y の左右の最大和を足す
    for (y in 1 until n - 1) {
        best = maxOf(best, left[y - 1] + right[y + 1])
    }
    return best
}
```

### 解答コード（別解：1回の走査で O(1) メモリ）

```kotlin
fun solution(A: IntArray): Int {
    var plain = 0 // i で終わる、まだ1つも飛ばしていない区間の最大和
    // i で終わる、1つ飛ばした区間の最大和。A[0] は飛ばせないので最初は「なし」
    var skip = Int.MIN_VALUE / 2
    var best = 0
    for (i in 1 until A.size - 1) {
        // A[i] を足して伸ばすか、A[i] 自身を飛ばす要素にするか
        skip = maxOf(skip + A[i], plain)
        plain = maxOf(0, plain + A[i])
        best = maxOf(best, skip)
    }
    return best
}
```

### 考え方とポイント

- 真ん中 `Y` を決めると、答えは「`Y` の直前で終わる最大和」＋「`Y` の直後から始まる最大和」になる。
- `left` は左から、`right` は右から、Kadane法（足して負になったら0に戻す）で作る。区間が空でもよいので0未満にしない。
- `A[0]` と `A[N-1]` は必ず `X` / `Z` の外側になり、和に入らない。だからループは `1` から `n-2` まで。
- 別解は「まだ飛ばしていない和」と「1つ飛ばした和」の2状態を持つ。`skip` を先に `plain` の古い値で更新するのが順番の要。
- 計算量は時間 O(N)。追加メモリは本命が O(N)、別解が O(1)。

### 試験で間違えやすい点

- 両端の `A[0]` と `A[N-1]` を和に入れてしまう（`A[0]` を飛ばす要素 `Y` にするのも不可）。`left` / `right` のループ範囲を `1 until n - 1` と `n - 2 downTo 1` にする。
- 普通の最大スライス（MaxSliceSum）と違い、空の区間が許されるので答えは0以上。全部負の数でも負の値は返さない。
- 別解の `skip` を0で始めると、`A[0]` を飛ばしたことになり `[0, 5, 0]` で5を返してしまう。最初は「まだ作れない」を表す小さな値にする。
- 和の最大は約 99,998 × 10,000 ≒ 10億で、`Int` の上限（約21億）に収まる。`Long` は要らない。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| `[5, 5, 5]` | 0 | 最小の N。真ん中しかなく何も足せない |
| `[-1, -2, -3, -4, -5]` | 0 | 全部負でも0 |
| `[10000, 1, 2, 3, 10000]` | 5 | 両端は入らない。一番小さい1を飛ばす |
| `[0, 10, -5, 20, 0]` | 30 | 負の数を Y にして飛ばす |
| `[0, 5, 6, 0]` | 6 | 内側が2個なら大きい方だけ残る |
| `[0, 5, 0]` | 0 | `A[0]` を飛ばす要素にできない（別解の初期値） |
| 10000 が 100,000 個 | 999970000 | 最大サイズで Int に収まる |
