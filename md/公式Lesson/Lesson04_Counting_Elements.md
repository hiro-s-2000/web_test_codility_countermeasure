# Lesson 4 Counting Elements（公式のlessonの問題）

> Codility公式の [Lesson 4: Counting Elements](https://app.codility.com/programmers/lessons/4-counting_elements/) の全問題を、Kotlinで解いた解答です。このLessonの問題は **FrogRiverOne**、**PermCheck**、**MaxCounters**、**MissingInteger** の4問です。
> 問題文は公式ページで読み、下の要約は確認用に使ってください。先に自分で解いてから、答え合わせに解答を開くのがおすすめです。

## FrogRiverOne（Easy）

> 公式の問題文: [FrogRiverOne](https://app.codility.com/programmers/lessons/4-counting_elements/frog_river_one/)

### 問題の要約

- カエルは位置0にいて、川の向こう岸の位置 `X+1` へ渡りたい。
- 毎秒1枚ずつ葉が落ちる。`A[K]` は、K秒目に葉が落ちる位置（1〜`X`）。
- 位置1〜`X` のすべてに葉がそろった、一番早い秒（添字K）を返す。最後までそろわなければ -1 を返す。
- `N`（配列の長さ）と `X` は 1〜100,000。`A` の要素は 1〜`X`。

| 入力 | 答え | 一言 |
|---|---|---|
| X = 5, A = [1, 3, 1, 4, 2, 3, 5, 4] | 6 | 6秒目に位置5へ葉が落ちて、1〜5がそろう |

### 解答コード（O(N)・見た位置を数える）

```kotlin
fun solution(X: Int, A: IntArray): Int {
    val seen = BooleanArray(X + 1)
    var left = X // まだ葉がない位置の数
    for (k in A.indices) {
        val p = A[k]
        if (!seen[p]) {
            seen[p] = true
            left--
            if (left == 0) return k
        }
    }
    return -1
}
```

### 考え方とポイント

- 新しい位置に葉が落ちるたびに「残りの数」を1減らし、0になった瞬間の秒を返す。
- 同じ位置に2枚目が落ちても数えないように、`BooleanArray` で「もう見た」を覚える。
- 「全部そろったか」を毎回1〜Xまで調べると O(N·X) で性能テストに落ちる。残り数を持てば O(1) で判定できる。
- 計算量は時間 O(N)、追加メモリ O(X)。

### 試験で間違えやすい点

- 返すのは秒（添字 `k`）で、位置 `p` ではない。
- 配列の大きさは `X + 1` にする。位置は1始まりなので `X` だと `A[k] == X` で範囲外になる。
- `N < X` のときは絶対にそろわない。ループを抜けたら -1 を返すのを忘れない。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| X = 1, A = [1] | 0 | 最小の入力。0秒目でそろう |
| X = 2, A = [1] | -1 | 葉の数が足りない |
| X = 2, A = [1, 1, 1] | -1 | 同じ位置ばかりで、そろわない |
| X = 3, A = [3, 2, 1] | 2 | 逆順でも最後の1枚でそろう |
| X = 3, A = [1, 3, 1, 3, 2, 2] | 4 | 重複のあとにそろう |
| X = 100000, A = [1, 2, …, 100000] | 99999 | 最大サイズ、最後の秒でそろう |

## PermCheck（Easy）

> 公式の問題文: [PermCheck](https://app.codility.com/programmers/lessons/4-counting_elements/perm_check/)

### 問題の要約

- 空でない整数配列 `A`（長さ N は 1〜100,000）が渡される。
- 要素の値は 1〜1,000,000,000。N より大きい値も来る。
- `A` が「1〜N をちょうど1回ずつ含む」順列なら 1、そうでなければ 0 を返す。
- 戻り値は `Boolean` ではなく `Int`（1 か 0）。

| 入力 A | 答え | 一言 |
|---|---|---|
| [4, 1, 3, 2] | 1 | 1〜4 が1回ずつそろう |
| [4, 1, 3] | 0 | N=3 なのに 4 があり、2 がない |

### 解答コード（O(N) 出現チェック）

```kotlin
fun solution(A: IntArray): Int {
    val n = A.size
    // seen[v] = 値 v をもう見たか（1〜n だけ記録する）
    val seen = BooleanArray(n + 1)
    for (a in A) {
        if (a > n) return 0       // 範囲外の値があれば順列ではない
        if (seen[a]) return 0     // 2回目が来たら重複
        seen[a] = true
    }
    // 長さ n で 1〜n の重複がなければ、全部そろっている
    return 1
}
```

### 解答コード（別解：ソートして並びを確かめる O(N log N)）

```kotlin
fun solution(A: IntArray): Int {
    val s = A.sorted()
    // 並べると 1, 2, ..., N になるはず
    for (i in s.indices) {
        if (s[i] != i + 1) return 0
    }
    return 1
}
```

### 考え方とポイント

- 1〜N の値ごとに「見たか」を記録し、範囲外の値か重複が出たら 0 を返す。
- 長さが N で、すべてが 1〜N に収まり、重複がなければ、N 個の値が全部ちがう＝1〜N が全部そろう。だから最後に欠けを数え直す必要はない。
- 記録用の配列は値の上限（10億）ではなく N+1 の大きさで足りる。N より大きい値は即 0 にするため。
- 計算量は時間 O(N)、追加メモリ O(N)。別解は時間 O(N log N)、追加メモリ O(N)（`sorted()` は元の配列を変えずにコピーを作る）。

### 試験で間違えやすい点

- 合計が N(N+1)/2 になるかだけで判定しない。[1, 4, 1, 4] は合計 10 で N=4 の和と同じだが順列ではない。しかも Int では和が溢れうる。
- `a > n` の確認を先にしないと、`seen[a]` で `ArrayIndexOutOfBoundsException` になる（値は最大10億）。
- `BooleanArray(n)` にすると添字 n が使えない。値をそのまま添字にするなら `n + 1` の大きさにする。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| [1] | 1 | 最小の順列 |
| [2] | 0 | N=1 で値が範囲外 |
| [1, 1] | 0 | 重複 |
| [1, 4, 1, 4] | 0 | 合計だけ合う偽物 |
| [1000000000] | 0 | 最大値の要素 |
| [2, 3, 1, 5, 4] | 1 | 並びがばらばらの順列 |
| 1〜100,000 を混ぜた配列 | 1 | 最大サイズ |

## MaxCounters（Medium）

> 公式の問題文: [MaxCounters](https://app.codility.com/programmers/lessons/4-counting_elements/max_counters/)

### 問題の要約

- カウンターが `N` 個（番号は1〜N）あり、最初はすべて0。
- 操作の列 `A`（長さ M）を先頭から順に実行する。
- `A[K]` が1〜Nなら、その番号のカウンターに1を足す。
- `A[K]` が `N + 1` なら、全カウンターを「その時点の最大値」にそろえる。
- 全操作のあとの各カウンターの値を `IntArray`（長さ N、0番目がカウンター1）で返す。
- 範囲: N と M は 1〜100,000。`A` の要素は 1〜N+1。

| 入力 | 答え | 一言 |
|---|---|---|
| N=5, A=[3, 4, 4, 6, 1, 4, 4] | [3, 2, 2, 4, 2] | 6（=N+1）で全員が2にそろう |

### 解答コード（O(N + M)、そろえる操作を遅らせる）

```kotlin
fun solution(N: Int, A: IntArray): IntArray {
    val c = IntArray(N)
    var base = 0 // 最後にそろえた値（全員これ以上）
    var max = 0  // 今の最大値
    for (x in A) {
        if (x == N + 1) {
            base = max // 全員を書き換えず、値だけ覚える
        } else {
            val i = x - 1
            if (c[i] < base) c[i] = base
            c[i]++
            if (c[i] > max) max = c[i]
        }
    }
    // 一度も足されなかったカウンターを base に引き上げる
    for (i in 0 until N) {
        if (c[i] < base) c[i] = base
    }
    return c
}
```

### 考え方とポイント

- 「全員を最大値にそろえる」を毎回やらず、その値を `base` に覚えておき、カウンターに触れる時と最後にだけ反映する。
- 足す前に `c[i] < base` なら `base` まで引き上げてから1を足す。これで「そろえた後に足した」のと同じ値になる。
- 最大値 `max` は足すたびに更新するだけでよい。そろえる操作では `max` は変わらない。
- 最後に1周して、`base` 未満のカウンターを `base` に引き上げる。
- 計算量は時間 O(N + M)、追加メモリは O(N)（返す配列のみ）。

### 試験で間違えやすい点

- そろえる操作のたびに配列全体を書き換えると O(N × M) になり、性能テストで時間切れになる（N=M=100,000 で最悪100億回）。
- カウンター番号は1始まり。配列の添字は `x - 1` にする。
- 最後の引き上げのループを忘れると、そろえた後に一度も足されなかったカウンターが古い値のまま残る。
- `max = base` のように最大値を戻してはいけない。そろえても最大値は同じ。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| N=1, A=[1] | [1] | 最小のサイズ |
| N=1, A=[2] | [0] | 全部0の時にそろえる |
| N=3, A=[4, 4, 4] | [0, 0, 0] | そろえる操作だけ |
| N=3, A=[1, 1, 4, 2] | [2, 3, 2] | そろえた後に足す |
| N=3, A=[2, 4, 4, 1, 4] | [2, 2, 2] | そろえる操作が続く・最後がそろえる |
| N=2, A=[1, 1, 1, 3, 2] | [3, 4] | 足されなかった方も引き上がる |

## MissingInteger（Medium）

> 公式の問題文: [MissingInteger](https://app.codility.com/programmers/lessons/4-counting_elements/missing_integer/)

### 問題の要約

- 整数の配列 `A`（長さ N は 1〜100,000）が渡される。
- 要素の値は -1,000,000〜1,000,000。負の数や0、重複も入る。
- `A` に出てこない「一番小さい正の整数（1以上）」を返す。
- 答えは必ず 1〜N+1 のどれかになる。

| A | 答え | 一言 |
|---|---|---|
| `[1, 3, 6, 4, 1, 2]` | 5 | 1〜4はあり、5がない |
| `[1, 2, 3]` | 4 | 全部そろえば N+1 |
| `[-1, -3]` | 1 | 正の数が1つもない |

### 解答コード（O(N)・出席表）

```kotlin
fun solution(A: IntArray): Int {
    val n = A.size
    // seen[v] = 値 v (1..n) が出てきたか。n より大きい値は答えに関係しない
    val seen = BooleanArray(n + 2)
    for (v in A) {
        if (v in 1..n) seen[v] = true
    }
    var x = 1
    while (seen[x]) x++
    return x
}
```

### 解答コード（別解：並べ替え O(N log N)）

```kotlin
fun solution(A: IntArray): Int {
    val s = A.sorted()
    var want = 1
    // 小さい順に見て、ちょうど want が来たら次を探す
    for (v in s) {
        if (v == want) want++
        else if (v > want) break
    }
    return want
}
```

### 考え方とポイント

- 1〜N の「出席表」を作り、最初に欠けている番号を探す。
- 長さ N の配列には正の数が最大 N 種類しか入らないので、答えは 1〜N+1 に収まる。だから表は N+2 個あれば足りる。
- 0以下の値と N より大きい値は、答えに影響しないので無視する。
- 計算量は時間 O(N)、追加メモリ O(N)。別解は並べ替えのぶん O(N log N) だが、それでも満点が取れる。

### 試験で間違えやすい点

- 表を値の最大値（1,000,000）や負の数まで含めて作ろうとすると、添字が負になって落ちる。`v in 1..n` だけを書き込む。
- 表のサイズを `n + 1` にすると、全部そろった時（`[1, 2, 3]`）に `seen[n + 1]` を読んで範囲外になる。`n + 2` にする。
- 別解で重複（`[1, 1, 2]`）を考えずに「`v == want` でなければ終わり」とすると間違える。`v < want` は読み飛ばす。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| `[1]` | 2 | 最小の N で全部そろう |
| `[2]` | 1 | 1 がない |
| `[-1000000, 0]` | 1 | 0 と負の数は無視 |
| `[1000000]` | 1 | 大きすぎる値は無視 |
| `[1, 1, 1, 2, 2]` | 3 | 重複 |
| `[4, 3, 2, 1]` | 5 | 逆順でも N+1 |
| `[1..100000]` | 100001 | 最大サイズで全部そろう |
