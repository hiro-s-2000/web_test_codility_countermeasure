> 問題文は公式ページで読み、下の要約は確認用に使ってください。先に自分で解いてから、答え合わせに解答を開くのがおすすめです。

## AbsDistinct（Easy）

> 公式の問題文: [AbsDistinct](https://app.codility.com/programmers/lessons/15-caterpillar_method/abs_distinct/)

### 問題の要約

- 空でない整数配列 `A`（長さ N は 1〜100,000）が渡される。
- `A` は小さい順（同じ値の並びあり）に並んでいる。
- 各要素の値は -2,147,483,648〜2,147,483,647（Int の全範囲）。
- 要素の絶対値を取ったとき、何種類の値があるかを返す。

| 入力 | 答え | 一言 |
|---|---|---|
| [-5, -3, -1, 0, 3, 6] | 5 | 絶対値は 0, 1, 3, 5, 6。-3 と 3 は同じ扱い |

### 解答コード（O(N)・両端からの尺取り）

```kotlin
import kotlin.math.abs

fun solution(A: IntArray): Int {
    var l = 0
    var r = A.size - 1
    var count = 0
    while (l <= r) {
        // Int.MIN_VALUE の絶対値は Int に入らないので Long で比べる
        val m = maxOf(abs(A[l].toLong()), abs(A[r].toLong()))
        count++
        // 絶対値が m の要素を両端から全部読み飛ばす
        while (l <= r && abs(A[l].toLong()) == m) l++
        while (l <= r && abs(A[r].toLong()) == m) r--
    }
    return count
}
```

### 解答コード（別解：Set で数える）

```kotlin
import kotlin.math.abs

fun solution(A: IntArray): Int {
    // Long にしてから絶対値を取り、重複を Set で消す
    return A.map { abs(it.toLong()) }.toSet().size
}
```

### 考え方とポイント

- 絶対値が大きいものは必ず配列の左端か右端にあるので、両端から大きい順に絶対値を1種類ずつ数える。
- 毎回、両端のうち絶対値の大きい方を `m` とし、絶対値が `m` の要素を左右とも読み飛ばして1と数える。同じ値の並びも、-3 と 3 の組もこれで一度に消える。
- 各要素は一度しか読み飛ばされないので、時間 O(N)、追加メモリ O(1)。
- 別解の Set 版も O(N) で通る。追加メモリは O(N) だが、短く書けて間違えにくい。

### 試験で間違えやすい点

- `abs(Int.MIN_VALUE)` は Int では `-2147483648` のままになる（溢れる）。必ず `toLong()` してから `abs` を取る。
- 内側の `while` に `l <= r` を付け忘れると、全部同じ値の配列などで範囲外アクセスになる。
- 左右を別々に1歩ずつ進める書き方だと、`[-1, -1, 1, 1]` のような重複で数え過ぎやすい。「絶対値 m を全部消す」とまとめると安全だ。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| [0] | 1 | 要素1つ |
| [-1, -1, 1, 1] | 1 | 重複と符号違いの両方 |
| [5, 5, 5, 5] | 1 | 全部同じ値 |
| [-3, -2, -1] | 3 | 負の数だけ |
| [-2147483648, 2147483647] | 2 | Int.MIN_VALUE の絶対値の溢れ |
| [-2147483648, -2147483647, 2147483647] | 2 | 最小値と最大値の絶対値の区別 |

## CountDistinctSlices（Easy）

> 公式の問題文: [CountDistinctSlices](https://app.codility.com/programmers/lessons/15-caterpillar_method/count_distinct_slices/)

### 問題の要約

- 整数 `M` と、長さ `N` の配列 `A` が渡される。`A` の要素はすべて 0〜`M` の整数。
- 連続した区間 `A[P..Q]`（0 ≤ P ≤ Q < N）のうち、同じ数が2回以上出てこない区間を「重複のないスライス」と呼ぶ。
- 重複のないスライスの個数を返す。ただし 1,000,000,000 を超えたら 1,000,000,000 を返す。
- 範囲: `N` は 1〜100,000、`M` は 0〜100,000。

| 入力 | 答え | 一言 |
|---|---|---|
| M = 6, A = [3, 4, 5, 5, 2] | 9 | (0,0) (0,1) (0,2) (1,1) (1,2) (2,2) (3,3) (3,4) (4,4) |

### 解答コード（尺取り法 O(N)）

```kotlin
fun solution(M: Int, A: IntArray): Int {
    val seen = BooleanArray(M + 1)  // 今の区間に入っている数
    var left = 0
    var count = 0L
    for (right in A.indices) {
        // A[right] が重複しなくなるまで左端を進める
        while (seen[A[right]]) {
            seen[A[left]] = false
            left++
        }
        seen[A[right]] = true
        // 右端が right の区間は left..right の始点ぶんある
        count += right - left + 1
        if (count > 1_000_000_000L) return 1_000_000_000
    }
    return count.toInt()
}
```

### 解答コード（別解：最後に出た位置を覚える）

```kotlin
fun solution(M: Int, A: IntArray): Int {
    val last = IntArray(M + 1) { -1 }  // 各数が最後に出た位置
    var left = 0
    var count = 0L
    for (i in A.indices) {
        // 同じ数が区間内にあれば、その次まで左端を飛ばす
        if (last[A[i]] >= left) left = last[A[i]] + 1
        last[A[i]] = i
        count += i - left + 1
        if (count > 1_000_000_000L) return 1_000_000_000
    }
    return count.toInt()
}
```

### 考え方とポイント

- 右端を1つずつ進め、重複が出たら左端を縮める尺取り法で「右端が `right` の重複なし区間の数 = `right - left + 1`」を足していく。
- 左端は戻らないので、`while` の中は全体で合計 N 回しか回らない。
- 要素の値が 0〜M なので、HashSet ではなく長さ `M + 1` の `BooleanArray` で出現を管理できる。
- 別解は、各数が最後に出た位置を持っておき、左端を一気に飛ばす。`while` が要らない。
- 計算量は時間 O(N + M)、追加メモリ O(M)。

### 試験で間違えやすい点

- 答えは最大 N(N+1)/2 ≒ 50億で Int に収まらない。`count` は `Long` にし、10億を超えたら10億を返す。
- 「10億を超えたら」なので、ちょうど 1,000,000,000 はそのまま返す（`>` で比べる）。
- 配列の大きさは `M` ではなく `M + 1`。値が `M` の要素があるので、`BooleanArray(M)` だと範囲外になる。
- 別解で `last[A[i]] >= left` の条件を忘れると、区間の外にある古い位置まで左端が戻ってしまう。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| M = 0, A = [0] | 1 | 最小のN・最小のM |
| M = 5, A = [1, 1, 1, 1] | 4 | 全部同じ値（長さ1の区間だけ） |
| M = 3, A = [0, 1, 2, 3] | 10 | 全部違う値（N(N+1)/2） |
| M = 2, A = [1, 2, 1, 2] | 7 | 重複が交互に出る |
| M = 3, A = [1, 2, 3, 1] | 9 | 左端を少しだけ進める |
| M = 100000, A = 0〜99999（N = 100,000） | 1000000000 | 上限で打ち切る |

## CountTriangles（Easy）

> 公式の問題文: [CountTriangles](https://app.codility.com/programmers/lessons/15-caterpillar_method/count_triangles/)

### 問題の要約

- 長さ `N`（0〜1,000）の整数配列 `A` が渡される。要素は 1〜1,000,000,000。
- 添字 `P < Q < R` の3つ組のうち、`A[P]`, `A[Q]`, `A[R]` を3辺とする三角形が作れるものの数を返す。
- 三角形の条件は「どの2辺の和も残りの1辺より大きい」（等しいのはだめ）。
- 3つ組は添字で数えるので、同じ値が複数あってもそれぞれ別に数える。

| 入力 | 答え | 一言 |
|---|---|---|
| `[10, 2, 5, 1, 8, 12]` | 4 | (10,5,8) (10,5,12) (10,8,12) (5,8,12) の4組 |

### 解答コード（O(N²) 尺取り）

```kotlin
fun solution(A: IntArray): Int {
    val a = A.sortedArray()
    val n = a.size
    var count = 0
    for (x in 0 until n) {
        var z = x + 2
        for (y in x + 1 until n) {
            // a[x] + a[y] > a[z] の間 z を右へ進める（z は戻らない）
            if (z < y + 1) z = y + 1
            while (z < n && a[x].toLong() + a[y] > a[z]) z++
            count += z - y - 1
        }
    }
    return count
}
```

### 考え方とポイント

- 並べ替えてから、一番小さい2辺 `a[x] + a[y]` が一番大きい辺 `a[z]` より大きいかだけを調べる。
- 並べ替え済みなら `a[x] <= a[y] <= a[z]` なので、残り2つの不等式は自動で成り立つ。
- `x` を固定すると、`y` が右へ進むほど `a[x] + a[y]` は大きくなるので、条件を満たす `z` の右端も右へしか動かない（尺取り）。
- `y` ごとに `y+1 .. z-1` の `z - y - 1` 個が三角形になる。
- 計算量は時間 O(N²)（ソート O(N log N) を含む）、追加メモリは O(N)（ソートした配列のコピー）。

### 試験で間違えやすい点

- `a[x] + a[y]` は最大 2,000,000,000 で Int を溢れる。`a[x].toLong() + a[y]` のように Long で足す。
- `y` が進んだとき `z` が `y + 1` より左に残ることがあるので、`z` を `y + 1` まで引き上げないと `z - y - 1` が負になる。
- 和と辺が等しい（例: 1, 2, 3）は三角形ではない。`>=` ではなく `>` で比べる。
- 答えは最大で C(1000, 3) = 166,167,000 なので Int に収まる。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| `[]` | 0 | 空配列 |
| `[5, 5]` | 0 | 3本ない |
| `[1, 2, 3]` | 0 | 和がちょうど等しいのは不可 |
| `[3, 4, 5]` | 1 | 最小の成立例 |
| `[1000000000, 1000000000, 1000000000]` | 1 | 和が Int を溢れる |
| `[1, 1, 1, 1]` | 4 | 同じ値を別々に数える |
| 1,000個すべて 1 | 166167000 | 最大件数 |

## MinAbsSumOfTwo（Medium）

> 公式の問題文: [MinAbsSumOfTwo](https://app.codility.com/programmers/lessons/15-caterpillar_method/min_abs_sum_of_two/)

### 問題の要約

- 空でない整数配列 `A`（長さ N は 1〜100,000）が渡される。
- 要素の値は −1,000,000,000〜1,000,000,000。
- `0 ≤ P ≤ Q < N` の組 (P, Q) について `|A[P] + A[Q]|` を考え、その最小値を返す。
- `P = Q` も許される。つまり同じ要素を2回使った `|2 × A[P]|` も候補に入る。

| 入力 | 答え | 一言 |
|---|---|---|
| `[1, 4, -3]` | 1 | `|4 + (-3)| = 1` |
| `[-8, 4, 5, -10, 3]` | 3 | `|(-8) + 5| = 3` |

### 解答コード（ソート＋両端から寄せる）

```kotlin
fun solution(A: IntArray): Int {
    A.sort()
    var i = 0
    var j = A.size - 1
    var best = Long.MAX_VALUE
    // i == j（同じ要素を2回使う）もループ内で調べる
    while (i <= j) {
        val s = A[i].toLong() + A[j].toLong()  // 和は最大 2×10^9 で Int に収まるが、念のため Long で計算する
        if (Math.abs(s) < best) best = Math.abs(s)
        if (s < 0) i++
        else if (s > 0) j--
        else return 0
    }
    return best.toInt()
}
```

### 考え方とポイント

- 並べ替えてから、左端 `i`（小さい値）と右端 `j`（大きい値）の和を見て、和が負なら `i` を右へ、正なら `j` を左へ寄せる（尺取り法）。
- 和が負のとき、`A[i]` と組む相手で一番0に近いのは今の `A[j]` 以下にはない（`j` より左はもっと小さい）ので、`A[i]` はもう使い終わってよい。正のときも同じ理屈で `A[j]` を捨てられる。
- `i <= j` まで回すので、`i == j` の時に `|2 × A[i]|` も調べられる。全部正（全部負）の配列でも正しく動く。
- 和がちょうど0なら、それ以上小さくならないのですぐ0を返す。
- 計算量は時間 O(N log N)（ソートが支配的）、追加メモリは O(1)（入力をその場でソート）。

### 試験で間違えやすい点

- この問題の制約（各値 ±10億）では、2つの和は最大 ±20億で Int（約±21.4億）に収まる。値の範囲がもう少し広い問題では溢れるので、和は Long で取る癖をつけておく。
- ループ条件を `i < j` にすると `P = Q` の候補が抜け、`[5]` で 10 を返せない（`best` が初期値のまま）。
- 答えの上限は理論上 2,000,000,000 で、戻り値の Int（最大 2,147,483,647）には収まる。和も答えも Int に収まる。
- `A.sort()` は元の配列を書き換える。問題ないが、テストで同じ配列を使い回すときは `copyOf()` を渡す。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| `[5]` | 10 | 1要素で P = Q |
| `[0]` | 0 | 0 だけ |
| `[1, 2, 3]` | 2 | 全部正なら 2 × 最小値 |
| `[-1, -2, -3]` | 2 | 全部負なら 2 × 最大値 |
| `[-5, 5]` | 0 | ちょうど打ち消す |
| `[-1000000000, -1000000000, 999999999]` | 1 | 値の範囲の端（大きな負の数）を含む |
| `[1000000000]` | 2000000000 | 答えの最大値（Int に収まる） |
