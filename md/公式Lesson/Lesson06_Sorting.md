> 問題文は公式ページで読み、下の要約は確認用に使ってください。先に自分で解いてから、答え合わせに解答を開くのがおすすめです。

## Distinct（Easy）

> 公式の問題文: [Distinct](https://app.codility.com/programmers/lessons/6-sorting/distinct/)

### 問題の要約

- 整数の配列 `A`（長さ N は 0〜100,000）が渡される。
- 各要素は -1,000,000〜1,000,000。
- 配列の中に出てくる値が何種類あるか（重複を除いた個数）を返す。
- N = 0（空配列）もありうる。そのときは0を返す。

| 入力 | 答え | 一言 |
|---|---|---|
| [2, 1, 1, 2, 3, 1] | 3 | 1, 2, 3 の3種類 |

### 解答コード（ソートして隣と比べる O(N log N)）

```kotlin
fun solution(A: IntArray): Int {
    if (A.isEmpty()) return 0
    val s = A.sortedArray()
    var count = 1
    for (i in 1 until s.size) {
        // 並べ替えると同じ値は隣り合うので、変わり目だけ数える
        if (s[i] != s[i - 1]) count++
    }
    return count
}
```

### 解答コード（別解：HashSet O(N)）

```kotlin
fun solution(A: IntArray): Int {
    // 重複を自動で捨てる集合に入れて、大きさを返す
    return A.toHashSet().size
}
```

### 考え方とポイント

- 並べ替えると同じ値が隣り合うので、「前の値と違う」場所を数えれば種類数になる。
- 最初の1個は必ず新しい値なので、`count` は1から始めて i = 1 から比べる。
- 時間は O(N log N)、追加メモリは O(N)（`sortedArray()` がコピーを作る）。
- 別解の HashSet は平均 O(N) で、試験ではこちらの方が速く書ける。Lesson の趣旨（ソート）を練習するなら本命の書き方を覚える。

### 試験で間違えやすい点

- 空配列で `count = 1` から始めると1を返してしまう。先に `A.isEmpty()` で0を返す。
- `A.sort()` は引数の配列そのものを書き換える。元の配列を残したいなら `sortedArray()` を使う（Codility の採点ではどちらでも通る）。
- `for (i in 1 until s.size)` は N = 1 のとき1回も回らないので、そのまま1が返る。`1..s.size` と書くと範囲外になる。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| [] | 0 | 空配列 |
| [5] | 1 | 要素1個 |
| [7, 7, 7, 7] | 1 | 全部同じ値 |
| [-1000000, 1000000, 0] | 3 | 最小値・最大値・負の数 |
| [-1, 1, -1, 1] | 2 | 符号違いを別の値として数える |
| [3, 2, 1] | 3 | 全部違う値 |

## MaxProductOfThree（Easy）

> 公式の問題文: [MaxProductOfThree](https://app.codility.com/programmers/lessons/6-sorting/max_product_of_three/)

### 問題の要約

- 長さ `N`（3〜100,000）の整数配列 `A` が渡される。要素は -1,000〜1,000。
- 添字の違う3つ（`P < Q < R`）を選び、`A[P] * A[Q] * A[R]` を作る。
- その積の最大値を返す。
- 負の数もあるので、「大きい順に3つ」だけが答えとは限らない。

| 入力 | 答え | 一言 |
|---|---|---|
| `[-3, 1, 2, -2, 5, 6]` | 60 | 2 × 5 × 6 が最大 |

### 解答コード（ソート O(N log N)）

```kotlin
fun solution(A: IntArray): Int {
    val a = A.sorted()
    val n = a.size
    // 大きい3つの積
    val top3 = a[n - 1] * a[n - 2] * a[n - 3]
    // 小さい2つ（負×負で正になる）× 一番大きい数
    val neg2 = a[0] * a[1] * a[n - 1]
    return maxOf(top3, neg2)
}
```

### 解答コード（別解：1回の走査 O(N)）

```kotlin
fun solution(A: IntArray): Int {
    // 大きい順に3つ（m1 >= m2 >= m3）と、小さい順に2つ（s1 <= s2）を覚える
    var m1 = Int.MIN_VALUE; var m2 = Int.MIN_VALUE; var m3 = Int.MIN_VALUE
    var s1 = Int.MAX_VALUE; var s2 = Int.MAX_VALUE
    for (x in A) {
        if (x > m1) { m3 = m2; m2 = m1; m1 = x }
        else if (x > m2) { m3 = m2; m2 = x }
        else if (x > m3) { m3 = x }
        if (x < s1) { s2 = s1; s1 = x }
        else if (x < s2) { s2 = x }
    }
    return maxOf(m1 * m2 * m3, s1 * s2 * m1)
}
```

### 考え方とポイント

- 並べ替えると、答えは「大きい3つの積」か「小さい2つ × 一番大きい数」のどちらかだ。
- 小さい2つが両方負なら、その積は大きな正の数になる。これに最大値を掛ける候補を忘れない。
- ほかの組み合わせ（小さい1つ × 大きい2つ など）は、この2候補を超えない。
- 積の最大は 1,000 × 1,000 × 1,000 = 10億で、`Int` の上限（約21億）に収まる。`Long` は要らない。
- 計算量はソート版が時間 O(N log N)・追加メモリ O(N)（`sorted()` が新しいリストを作る）。別解は時間 O(N)・追加メモリ O(1)。

### 試験で間違えやすい点

- 大きい3つだけを掛けて終わりにしない。`[-10, -10, 1, 3, 2]` の答えは 300（-10 × -10 × 3）で、大きい3つだと 6 になる。
- 全部負の数のときは、大きい3つ（絶対値が小さい3つ）の積が答えになる。2候補の `maxOf` を取れば自然に正しくなる。
- `A.sort()` は渡された配列そのものを書き換える。`A.sorted()` なら元の配列は変わらず、`List<Int>` が返る。
- 別解で `else if` を `if` にすると、同じ値が m1 と m2 の両方に入るなどして壊れる。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| `[1, 2, 3]` | 6 | 最小の N |
| `[-10, -10, 1, 3, 2]` | 300 | 負×負×最大が勝つ |
| `[-5, -6, -4, -7, -10]` | -120 | 全部負の数 |
| `[-4, -3, -2, 1]` | 12 | 正の数が1つだけ |
| `[-2, -3, 0, -1]` | 0 | 0 を含む |
| `[-1000, -1000, 1000]` | 1000000000 | 最大の積（Int に収まる） |

## Triangle（Easy）

> 公式の問題文: [Triangle](https://app.codility.com/programmers/lessons/6-sorting/triangle/)

### 問題の要約

- 整数の配列 `A`（長さ N は 0〜100,000、各要素は -2,147,483,648〜2,147,483,647）が渡される。
- 添字 `P < Q < R` の3つを選び、どの2つの和も残り1つより大きい（三角形が作れる）組があるか調べる。
- あれば1、なければ0を返す。
- 要素は負の数も入りうる。添字の順番は関係なく、3つの値の組み合わせだけで決まる。

| 入力 | 答え | 一言 |
|---|---|---|
| `[10, 2, 5, 1, 8, 20]` | 1 | 10, 5, 8 で三角形が作れる |
| `[10, 50, 5, 1]` | 0 | どの3つを選んでも作れない |

### 解答コード（ソートして隣の3つを見る O(N log N)）

```kotlin
fun solution(A: IntArray): Int {
    val a = A.sortedArray()
    for (i in 0 until a.size - 2) {
        // 小さい2つの和が一番大きい値を超えれば三角形になる
        // Int の和は溢れるので Long で足す
        if (a[i].toLong() + a[i + 1] > a[i + 2]) return 1
    }
    return 0
}
```

### 考え方とポイント

- ソートして、隣り合う3つ `a[i] <= a[i+1] <= a[i+2]` だけを調べれば十分だ。
- 並んだ3つなら、`a[i] + a[i+1] > a[i+2]` の1本を見るだけでよい。残りの2本は、大きい方が必ず勝つので自動で成り立つ（正の数のとき）。
- 一番大きい辺を `a[k]` に決めたとき、相方は「それより小さい中で一番大きい2つ」が最も有利だ。それがちょうど `a[k-1]` と `a[k-2]` なので、隣だけ見れば漏れがない。
- 負の数や0が混ざっても、条件 `a[i] + a[i+1] > a[i+2]` が成り立つのは3つとも正のときだけなので、この判定のままでよい。
- 計算量は時間 O(N log N)、追加メモリ O(N)（ソート済みのコピー）。

### 試験で間違えやすい点

- **Int の和が溢れる。** `2147483647 + 2147483647` は Int では負の数になり、正しい答えが0になる。`a[i].toLong() + a[i + 1]` のように片方を Long にしてから足す。
- `0 until a.size - 2` は N が0〜2のとき空の範囲になるので、そのまま0を返せる。別に分岐を書かなくてよい。
- `A.sort()` を使うと渡された配列を書き換える。Codility では通るが、元の配列を使い回す場面では `sortedArray()` が安全だ。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| `[]` | 0 | 空の配列 |
| `[5, 5]` | 0 | 要素が2つしかない |
| `[1, 1, 1]` | 1 | 最小の三角形 |
| `[1, 2, 3]` | 0 | 和がちょうど等しいときは作れない |
| `[-1, -1, -1]` | 0 | 負の数だけ |
| `[2147483647, 2147483647, 2147483647]` | 1 | Int で足すと溢れる |
| `[-2147483648, 2147483647, 2147483647, 1]` | 1 | 最小値と最大値が混ざる |

## NumberOfDiscIntersections（Medium）

> 公式の問題文: [NumberOfDiscIntersections](https://app.codility.com/programmers/lessons/6-sorting/number_of_disc_intersections/)

### 問題の要約

- 配列 `A`（長さ N は 0〜100,000）が渡される。要素は 0〜2,147,483,647。
- 円 J は中心 `(J, 0)`、半径 `A[J]`。つまり x 軸上の区間 `[J - A[J], J + A[J]]` を占める。
- 2つの円が1点でも共有すれば（境界で接するだけでも）「交わる」とする。
- 交わる円のペア（順番は区別しない）の数を返す。10,000,000 を超えたら -1 を返す。

| 入力 | 答え | 一言 |
|---|---|---|
| `[1, 5, 2, 1, 4, 0]` | 11 | 円1と円4は全部と交わり、円2は円0・円3とも交わる |

### 解答コード（ソート＋2本の指 O(N log N)）

```kotlin
fun solution(A: IntArray): Int {
    val n = A.size
    // 左端と右端を別々に並べる（Int だと溢れるので Long）
    val lo = LongArray(n) { it.toLong() - A[it] }
    val hi = LongArray(n) { it.toLong() + A[it] }
    lo.sort()
    hi.sort()
    var pairs = 0L
    var j = 0
    for (i in 0 until n) {
        // 右端が hi[i] の円より前に始まる円を数える
        while (j < n && lo[j] <= hi[i]) j++
        // そのうち自分と、すでに数えた i 個を除く
        pairs += j - i - 1
        if (pairs > 10_000_000) return -1
    }
    return pairs.toInt()
}
```

### 解答コード（別解：区間の始まりと終わりを数える O(N)）

```kotlin
fun solution(A: IntArray): Int {
    val n = A.size
    val start = IntArray(n)
    val end = IntArray(n)
    for (i in 0 until n) {
        // 端は 0〜n-1 に切り詰めても交わり方は変わらない
        start[maxOf(0L, i.toLong() - A[i]).toInt()]++
        end[minOf(n - 1L, i.toLong() + A[i]).toInt()]++
    }
    var open = 0L
    var pairs = 0L
    for (p in 0 until n) {
        val s = start[p].toLong()
        // 新しく始まる円は、開いている円すべてと、同時に始まる円同士で交わる
        pairs += open * s + s * (s - 1) / 2
        if (pairs > 10_000_000) return -1
        open += s - end[p]
    }
    return pairs.toInt()
}
```

### 考え方とポイント

- 円を x 軸上の区間 `[i - A[i], i + A[i]]` と見て、「重なる区間のペア数」を数える問題にする。
- 本命: 右端の小さい順に円を見ていく。右端 `hi[i]` 以下で始まる円の数 `j` から、自分と、右端がもっと小さくてすでにペアを数えた `i` 個を引くと、新しいペアの数 `j - i - 1` になる。
- 左端と右端を別々にソートしてよいのは、「どの円の端か」は要らず、個数だけ分かればよいから。
- 別解: 端を 0〜N-1 に切り詰め、各位置で始まる数・終わる数を数えて左から走査する。同じ位置で「始まる」を先、「終わる」を後に処理するので、接するだけの円も数えられる。
- 計算量は本命が時間 O(N log N)・追加メモリ O(N)、別解が時間 O(N)・追加メモリ O(N)。

### 試験で間違えやすい点

- `i + A[i]` は `A[i]` が 2,147,483,647 だと Int で溢れて負になる。`i.toLong() + A[i]` のように Long で計算する。
- 二重ループ O(N²) は N=100,000 で性能テストが通らない。
- 境界で接するだけでも交わりなので、比較は `<`ではなく `<=`（`lo[j] <= hi[i]`）。
- -1 の判定は「10,000,000 を超えたら」。ちょうど 10,000,000 は -1 にしない。ペア数も Long で数え、途中で超えたらすぐ返す。

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| `[]` | 0 | 空配列 |
| `[5]` | 0 | 円が1つだけ |
| `[0, 0]` | 0 | 半径0同士は離れている |
| `[1, 0]` | 1 | 境界で接するだけでも数える |
| `[2147483647, 0]` | 1 | 半径が最大値でも溢れない |
| 長さ 4472、全部 1,000,000 | 9997156 | 10,000,000 以下なのでそのまま返す |
| 長さ 4473、全部 1,000,000 | -1 | 10,000,000 を超えたら -1 |
