## FibFrog（Medium）

> 公式の問題文: [FibFrog](https://app.codility.com/programmers/lessons/13-fibonacci_numbers/fib_frog/)

### 問題の要約

- カエルが位置 -1（左岸）から位置 N（右岸）へ川を渡る。
- 配列 `A`（長さ N、0〜100,000）の `A[i]` は位置 i に葉があれば1、なければ0。着地できるのは葉の上と岸だけ。
- 1回のジャンプの距離はフィボナッチ数（1, 2, 3, 5, 8, …）で、前（右）にしか跳べない。
- 右岸に着くまでの最小ジャンプ回数を返す。渡れなければ -1 を返す。

| 入力 | 答え | 一言 |
|---|---|---|
| `[0, 0, 0, 1, 1, 0, 1, 0, 0, 0, 0]` | 3 | 5 → 2 → 5 と跳ぶ（-1 → 4 → 6 → 11） |

### 解答コード（DP O(N log N)）

```kotlin
fun solution(A: IntArray): Int {
    val n = A.size
    // 距離 n+1 以下のフィボナッチ数（1, 2, 3, 5, …）を集める
    val fibs = ArrayList<Int>()
    var a = 1
    var b = 2
    while (a <= n + 1) {
        fibs.add(a)
        val t = a + b
        a = b
        b = t
    }
    // dp[p] = 位置 p-1 に着く最小回数（p=0 が左岸、p=n+1 が右岸）
    val dp = IntArray(n + 2) { -1 }
    dp[0] = 0
    for (p in 1..n + 1) {
        if (p <= n && A[p - 1] == 0) continue
        for (f in fibs) {
            if (f > p) break
            val prev = dp[p - f]
            if (prev >= 0 && (dp[p] == -1 || prev + 1 < dp[p])) dp[p] = prev + 1
        }
    }
    return dp[n + 1]
}
```

### 考え方とポイント

- 位置を1つずらして「0 が左岸、n+1 が右岸」とし、各着地点への最小回数を左から順に決める DP にする。
- ある地点へは「そこからフィボナッチ数だけ手前の地点」から来るしかないので、`dp[p] = min(dp[p - f]) + 1` で求まる。
- 100,001 以下のフィボナッチ数は25個ほどしかないので、内側のループは短い。
- 計算量は時間 O(N log N)（フィボナッチ数の個数が log N 程度）、追加メモリ O(N)。
- 位置ごとではなく BFS（キュー）で広げても同じ答えになる。

### 試験で間違えやすい点

- 岸から岸の距離は N ではなく N+1。`N = 0`（空配列）でも距離1のジャンプで渡れるので答えは1、0 や -1 ではない。
- フィボナッチ数に 0 を入れると、その場に止まるジャンプになる。1（F(1)=F(2)）は重複して入れても害はないが、0 は除く。
- 右岸（p = n+1）は葉の有無に関係なく着地できる。`A[n]` を読むと範囲外になる。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| `[]` | 1 | N=0 でも距離1で渡れる |
| `[0]` | 1 | 距離2を1回で跳ぶ |
| `[0, 0, 0, 0, 0, 0, 0]` | 1 | 距離8を1回で跳ぶ |
| `[0, 0, 0, 0, 0]` | -1 | 距離6はフィボナッチ数でなく渡れない |
| `[1, 1, 1, 1, 1]` | 2 | 葉が全部ある（3 → 3 など） |
| `[0, 0, 0, 1, 1, 0, 1, 0, 0, 0, 0]` | 3 | 公式の例 |

## Ladder（Medium）

> 公式の問題文: [Ladder](https://app.codility.com/programmers/lessons/13-fibonacci_numbers/ladder/)

### 問題の要約

- 段数 N のはしごを、1回に1段か2段ずつ登って、ちょうど N 段目で止まる登り方の数を考える。
- 長さ L の配列 `A` と `B` が渡される。i 番目の答えは「A[i] 段の登り方の数」を 2^B[i] で割った余り。
- L 個の答えを `IntArray` で返す。
- 範囲: L は 1〜50,000、A[i] は 1〜L、B[i] は 1〜30。

| 入力 | 答え | 一言 |
|---|---|---|
| A = [4, 4, 5, 5, 1], B = [3, 2, 4, 3, 1] | [5, 1, 8, 0, 1] | 4段は5通り、5段は8通り、1段は1通り |

### 解答コード（フィボナッチを 2^30 で割った余りで前計算）

```kotlin
fun solution(A: IntArray, B: IntArray): IntArray {
    val n = A.size
    val mask30 = (1 shl 30) - 1
    // ways[k] = k段の登り方の数 を 2^30 で割った余り
    val ways = IntArray(n + 2)
    ways[0] = 1
    ways[1] = 1
    for (k in 2..n + 1) {
        ways[k] = (ways[k - 1] + ways[k - 2]) and mask30
    }
    val res = IntArray(n)
    for (i in 0 until n) {
        // 2^B で割った余り = 下位 B ビットだけ残す
        res[i] = ways[A[i]] and ((1 shl B[i]) - 1)
    }
    return res
}
```

### 考え方とポイント

- k 段の登り方は「最後が1段なら k-1 段の登り方、2段なら k-2 段の登り方」なので ways[k] = ways[k-1] + ways[k-2]（フィボナッチ数）になる。
- 本当の値は巨大になるので、最大の割る数 2^30 の余りだけ持つ。2^30 の余りから 2^B（B ≤ 30）の余りは、下位 B ビットを取れば正しく出る。
- 2^B で割った余りは `x and ((1 shl B) - 1)` で取れる。`%` でも同じ結果だが、ビット演算のほうが速く意味もはっきりする。
- A[i] ≤ L なので、L+1 までの表を1回作れば全質問に O(1) で答えられる。
- 計算量は時間 O(L)、追加メモリ O(L)。

### 試験で間違えやすい点

- 足し算のたびに余りを取らないと Int が溢れる。2^30 未満どうしの和は 2^31 未満なので、毎回 `and mask30` すれば Int で足りる。
- 質問ごとに 2^B[i] で余りを取りながら表を作り直すと O(L^2) になり性能テストで落ちる。表は 2^30 で1回だけ作る。
- `1 shl B[i] - 1` と書くと、`-` が `shl` より先に結び付いて `1 shl (B[i] - 1)` になる。`(1 shl B[i]) - 1` と括弧を付ける。
- ways[0] = 1、ways[1] = 1 から始める（1段の登り方は1通り、2段は2通り）。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| A = [1], B = [1] | [1] | 最小の入力 |
| A = [2, 1], B = [1, 30] | [0, 1] | 2段は2通りで、2で割ると0 |
| A = [3, 3, 3], B = [1, 2, 30] | [1, 3, 3] | 同じ段数で B だけ違う |

| L = 50000、A は全部 50000、B は全部 30 | 時間内に終わる | 最大サイズの性能 |
