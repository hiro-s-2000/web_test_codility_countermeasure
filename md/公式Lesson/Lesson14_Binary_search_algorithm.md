## MinMaxDivision（Medium）

> 公式の問題文: [MinMaxDivision](https://app.codility.com/programmers/lessons/14-binary_search_algorithm/min_max_division/)

### 問題の要約

- 整数 `K`、`M` と、長さ `N` の配列 `A` が渡される。`A` の要素はすべて 0〜`M`。
- `A` を前から順に、連続した `K` 個のブロックに区切る。空のブロックがあってもよい。
- 各ブロックの和のうち一番大きいものを「大きい和」と呼ぶ。区切り方を工夫して、大きい和を最小にした値を返す。
- 範囲: `N`、`K` は 1〜100,000。`M` は 0〜10,000。
- 全要素の和は最大 100,000 × 10,000 = 10億で、Int にぎりぎり収まる。

| 入力 | 答え | 一言 |
|---|---|---|
| K=3, M=5, A=[2, 1, 5, 1, 2, 2, 2] | 6 | [2, 1] [5, 1] [2, 2, 2] と分けると和は 3, 6, 6 |

### 解答コード（答えを二分探索 O(N log(N·M))）

```kotlin
fun solution(K: Int, M: Int, A: IntArray): Int {
    // 上限 limit でブロックが K 個以内に収まるか
    fun ok(limit: Int): Boolean {
        var blocks = 1
        var sum = 0
        for (x in A) {
            if (sum + x > limit) {
                blocks++
                sum = x
                if (blocks > K) return false
            } else {
                sum += x
            }
        }
        return true
    }
    var lo = A.max()   // 最大要素より小さい答えはない
    var hi = A.sum()   // ブロック1つなら全体の和
    while (lo < hi) {
        val mid = lo + (hi - lo) / 2   // この問題では (lo + hi) / 2 でも溢れないが、溢れにくい形で書く
        if (ok(mid)) hi = mid else lo = mid + 1
    }
    return lo
}
```

### 考え方とポイント

- 答えそのもの（大きい和の上限）を二分探索し、「その上限でK個以内に分けられるか」を貪欲に判定する。
- 判定は前から足していき、上限を超えそうになったら新しいブロックを始める。こうして作ったブロック数が最少になる。
- 上限を上げるほど分けやすくなる（単調）ので、二分探索が使える。分けられる最小の上限が答え。
- 探索範囲は下限が最大要素、上限が全体の和。下限を最大要素にしておけば、1要素だけで上限を超える場合を考えなくてよい。
- `M` は使わなくても解ける（探索範囲を `0..N*M` にする時に使える）。
- 計算量は O(N log(N·M))、追加メモリは O(1)。

### 試験で間違えやすい点

- この問題の上限では `lo + hi` は最大20億で、Int（約21.4億）にぎりぎり収まる。上限が少し大きい問題では溢れるので、`lo + (hi - lo) / 2` と書く癖をつける。
- 下限を0にすると、判定の中で「1要素だけで上限を超える」場合を別に扱う必要があり、バグの元になる。下限は `A.max()` にする。
- `K` が `N` より大きくてもよい（空のブロックが許される）。その時の答えは最大要素。
- 判定で「`sum + x > limit` なら新しいブロック」と `>` を使う。`>=` にすると、ちょうど上限に等しいブロックを作れずに答えが1大きくなる。

|---|---|---|

## NailingPlanks（Medium）

> 公式の問題文: [NailingPlanks](https://app.codility.com/programmers/lessons/14-binary_search_algorithm/nailing_planks/)

### 問題の要約

- 板が N 枚ある。K 番目の板は区間 `[A[K], B[K]]`（両端を含む）を占める。
- 釘が M 本あり、I 番目の釘は位置 `C[I]` に打てる。釘は先頭から順に使う。
- 板の区間内に釘が1本でもあれば、その板は留まる。
- 先頭から J 本だけ使って全部の板が留まる、最小の J を返す。全部使っても無理なら `-1`。
- N と M は 1〜30,000。A, B, C の値は 1〜2M。`A[K] ≤ B[K]`。

| 入力 | 答え | 一言 |
|---|---|---|
| A=[1,4,5,8], B=[4,5,9,10], C=[4,6,7,10,2] | 4 | 板 (8,10) は4本目の釘 10 で初めて留まる |

### 解答コード（答え J を二分探索＋累積和 O((N+M) log M)）

```kotlin
fun solution(A: IntArray, B: IntArray, C: IntArray): Int {
    val maxPos = 2 * C.size
    // 先頭 j 本の釘で全部の板が留まるか
    fun ok(j: Int): Boolean {
        val cnt = IntArray(maxPos + 1)
        for (i in 0 until j) cnt[C[i]]++
        for (p in 1..maxPos) cnt[p] += cnt[p - 1] // cnt[p] = 位置 p 以下の釘の数
        for (k in A.indices) {
            if (cnt[B[k]] - cnt[A[k] - 1] == 0) return false
        }
        return true
    }
    var lo = 1
    var hi = C.size
    if (!ok(hi)) return -1
    while (lo < hi) {
        val mid = (lo + hi) / 2
        if (ok(mid)) hi = mid else lo = mid + 1
    }
    return lo
}
```

### 考え方とポイント

- 釘を増やすほど留まる板は増えるだけなので、「J 本で全部留まるか」は J について単調。だから答え J を二分探索する。
- 判定は、先頭 J 本の釘の位置を数えて累積和にすれば、板1枚を `cnt[B] - cnt[A-1] > 0` で O(1) に調べられる。
- 位置は 1〜2M に収まるので、長さ 2M+1 の配列で数えられる（ソート不要）。
- 先に `ok(M)` を調べ、全部使っても無理なら `-1` を返す。
- 計算量は時間 O((N+M) log M)、追加メモリは O(M)。

### 試験で間違えやすい点

- `-1` を返す場合を忘れやすい。公式の例には出てこない。
- 板は両端を含むので、区間の釘の数は `cnt[B] - cnt[A - 1]`。`cnt[A]` を引くと、A ちょうどの釘を落とす。
- 板ごとに釘を全部なめる O(N×M) は、N=M=30,000 で 9億回になり性能テストで落ちる。
- 二分探索は `ok(mid)` が真なら `hi = mid`（mid も答えの候補）、偽なら `lo = mid + 1`。逆にすると無限ループや1ずれになる。
