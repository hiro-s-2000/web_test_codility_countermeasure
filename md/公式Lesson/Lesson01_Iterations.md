## BinaryGap（Easy）

> 公式の問題文: [BinaryGap](https://app.codility.com/programmers/lessons/1-iterations/binary_gap/)

### 問題の要約

- 正の整数 `N`（1〜2,147,483,647）が渡される。
- `N` を2進数で書いたとき、**両端を1で挟まれた0の並び**を「バイナリギャップ」と呼ぶ。
- 一番長いバイナリギャップの長さを返す。ギャップがなければ0を返す。
- 末尾の0（例: `100000` の `00000`）は右端が1で閉じていないので、ギャップに数えない。

| N | 2進数 | 答え |
|---|---|---|
| 9 | `1001` | 2 |
| 529 | `1000010001` | 4 |
| 20 | `10100` | 1 |
| 15 | `1111` | 0 |
| 32 | `100000` | 0 |
| 1041 | `10000010001` | 5 |

### 解答コード（ビット演算版）

```kotlin
fun solution(N: Int): Int {
    var n = N
    // 末尾の0は右端が1で閉じないので、先に捨てる
    while (n > 0 && (n and 1) == 0) {
        n = n shr 1
    }
    var best = 0
    var cur = 0
    while (n > 0) {
        if ((n and 1) == 0) {
            cur++
        } else {
            if (cur > best) best = cur
            cur = 0
        }
        n = n shr 1
    }
    return best
}
```

### 解答コード（文字列版）

```kotlin
fun solution(N: Int): Int {
    // 末尾の0を落としてから1で区切ると、残る塊がすべてギャップになる
    return N.toString(2).trimEnd('0').split('1').maxOf { it.length }
}
```

### 考え方とポイント

- **下の桁から1ビットずつ見る**。`n and 1` で一番下の桁を取り出し、`n shr 1` で1桁ずらす。
- 0が続く間は `cur` を数え、1が来たら「ギャップが閉じた」ので `best` を更新して `cur` を0に戻す。
- 末尾の0を先に捨てるのが一番の落とし穴。捨てないと、`32`（`100000`）で5を返してしまう。
- 左端は必ず1（先頭の0は書かない）なので、左側の閉じ忘れは起きない。
- 計算量は O(log N)（最大31桁）、追加メモリは O(1)。

### 試験で間違えやすい点

- **`and` と `==`、`+` の結び付きの順に注意する。** Kotlinでは `and` などの中置関数は `==` より先に、`+` より後に結び付く。`n and 1 == 0` は `(n and 1) == 0` と同じ意味で動くが、Java の `n & 1 == 0` はエラーになるなど言語によって逆なので、読み手のために `(n and 1) == 0` と括弧を付けて書く。`n and 1 + 1` は `n and (1 + 1)` になる点にも注意。
- 文字列版の `split('1')` は、`"1001"` を `["", "00", ""]` に分ける。両端の空文字も入るが、長さ0なので最大値には影響しない。
- `N` は正の数だけなので、`shr`（算術シフト）でも `ushr` でも結果は同じ。負の数が来る問題では `ushr` を使う。
