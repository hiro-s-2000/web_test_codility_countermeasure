# Lesson 17 Dynamic programming（公式のlessonの問題）

> Codility公式の [Lesson 17: Dynamic programming](https://app.codility.com/programmers/lessons/17-dynamic_programming/) の全問題を、Kotlinで解いた解答です。このLessonの問題は **NumberSolitaire**、**MinAbsSum** の2問です。
> 問題文は公式ページで読み、下の要約は確認用に使ってください。先に自分で解いてから、答え合わせに解答を開くのがおすすめです。

## NumberSolitaire（Medium）

> 公式の問題文: [NumberSolitaire](https://app.codility.com/programmers/lessons/17-dynamic_programming/number_solitaire/)

### 問題の要約

- 長さ `N`（2〜100,000）の配列 `A` が盤のマス目。各値は −10,000〜10,000。
- コマはマス0から始め、1回に1〜6マス前へ進む（盤の外へは出られない）。マス `N − 1` に着いたら終わり。
- 止まったマス（マス0とマス `N − 1` を含む）の値の合計が得点。得点の最大値を返す。
- 負のマスを避けたくても、6マスより先へは跳べないので、どこかに止まる必要がある。

| A | 答え | 一言 |
|---|---|---|
| `[1, -2, 0, 9, -1, -2]` | 8 | マス0→3→5 で 1 + 9 + (−2) |

### 解答コード（DP O(N)）

```kotlin
fun solution(A: IntArray): Int {
    val n = A.size
    // dp[i] = マス i に止まった時の最大得点
    val dp = IntArray(n)
    dp[0] = A[0]
    for (i in 1 until n) {
        var best = Int.MIN_VALUE
        // 1〜6マス手前のうち、一番良いところから来る
        for (k in 1..6) {
            if (i - k >= 0 && dp[i - k] > best) best = dp[i - k]
        }
        dp[i] = best + A[i]
    }
    return dp[n - 1]
}
```

### 考え方とポイント

- マス `i` に来る直前は「1〜6マス手前のどれか」なので、`dp[i] = A[i] + max(dp[i-1], …, dp[i-6])` で前から埋める。
- マス0は必ず止まるので `dp[0] = A[0]`。答えは `dp[N-1]`。
- 手前を最大6個見るだけなので、時間は O(6N) = O(N)、追加メモリは O(N)（直近6個だけ持てば O(1) にもできる）。
- 得点の絶対値は最大でも 100,000 × 10,000 = 1,000,000,000 で、`Int` の上限（約21億）に収まる。

### 試験で間違えやすい点

- `best` の初期値を `0` にしない。手前が全部負のとき、0 を足したことになり答えが大きくなる。`[0, -1, -1, -1, -1, -1, -1, -1, 0]` の正解は −1 だが、初期値0だと 0 を返してしまう。
- `best` を `Int.MIN_VALUE` で始めても、`i ≥ 1` なら `k = 1`（1つ手前）が必ずあるので上書きされ、`Int.MIN_VALUE + A[i]` の溢れは起きない。
- 最後のマス `N − 1` の値も必ず足す。負でも避けられない（`[3, -5]` の答えは −2）。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| `[3, -5]` | −2 | 最小のN、最後のマスが負でも足す |
| `[1, 2, 3, 4, 5, 6, 7]` | 28 | 全部正なら全マスに止まる |
| `[0, -1, -1, -1, -1, -1, -1, -1, 0]` | −1 | 7マス先は跳べないので1回は負に止まる |
| `[5, -9, -9, -9, -9, -9, 5]` | 10 | ちょうど6マス跳ぶ |
| 全部 10000、N = 100000 | 1000000000 | 最大値でも Int に収まる |
| 全部 −10000、N = 100000 | −166680000 | なるべく大きく跳んで止まる回数を減らす |

## MinAbsSum（Hard）

> 公式の問題文: [MinAbsSum](https://app.codility.com/programmers/lessons/17-dynamic_programming/min_abs_sum/)

### 問題の要約

- 整数の配列 `A`（長さ N は 0〜20,000、各要素は -100〜100）が渡される。
- 各要素に `+1` か `-1` の符号を付けて全部足す。
- その合計の絶対値として作れる最小の値を返す。
- 空配列の合計は0とみなすので、N = 0 なら0を返す。

| A | 答え | 一言 |
|---|---|---|
| `[1, 5, 2, -2]` | 0 | `-1 + 5 - 2 + (-2)` で0になる |

### 解答コード（値ごとの個数でDP O(N + M·S)）

```kotlin
fun solution(A: IntArray): Int {
    // 符号は自由なので絶対値だけ見ればよい。値ごとに個数を数える
    val cnt = IntArray(101)
    var s = 0
    for (x in A) {
        val v = Math.abs(x)
        cnt[v]++
        s += v
    }
    val half = s / 2
    // dp[j]: 和 j を作ったあと、今の値 v がまだ何個残っているか（-1 は作れない）
    val dp = IntArray(half + 1) { -1 }
    dp[0] = 0
    for (v in 1..100) {
        if (cnt[v] == 0) continue
        for (j in 0..half) {
            if (dp[j] >= 0) dp[j] = cnt[v]               // v を使わずに作れた
            else if (j >= v && dp[j - v] > 0) dp[j] = dp[j - v] - 1 // v をもう1個使う
        }
    }
    // 片側の和 j が s/2 に近いほど、差 s - 2j が小さい
    var j = half
    while (dp[j] < 0) j--
    return s - 2 * j
}
```

### 考え方とポイント

- 要素を「+のグループ」と「-のグループ」に分け、片方の和 j をできるだけ s/2（s は絶対値の合計）に近づける問題に言い換える。答えは `s - 2j`。
- 値は 0〜100 の101種類しかないので、要素ごとではなく「値ごと」にDPを回す。`dp[j]` に「和 j を作ったあと、今の値があと何個使えるか」を持たせると、個数制限付きの部分和を1回の走査で処理できる。
- `dp[j] >= 0`（前の値までで作れた）なら残り個数を `cnt[v]` に戻す。作れていなければ `dp[j - v]` から1個使って作る。
- 時間は O(N + M·S)（M = 100、S = 絶対値の合計で最大 2,000,000）。s/2 までしか見ないので実際は約1億回。追加メモリは O(S)。
- 要素ごとに true/false の部分和DPを回すと O(N·S) = 最大 4×10^10 になり、性能テストで落ちる。

### 試験で間違えやすい点

- 負の数をそのまま部分和に入れると添字が負になる。符号は自由に付けられるので、先に `Math.abs` で絶対値にしてよい。
- `dp` の更新は j を小さい順に回す。同じ配列の `dp[j - v]` はこの値 v の回ですでに更新済みで、「v をもう1個使った」状態を表すので、順番を逆にすると同じ値を何個使ったかが数えられない。
- 0 の要素は答えに影響しないので `v` は 1 から回す。N = 0 でも `s = 0`、`dp = [0]` となり0を返す。
- 合計は最大 20,000 × 100 = 2,000,000 なので Int で溢れない。

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| `[]` | 0 | 空配列 |
| `[-7]` | 7 | 要素1個、負の数 |
| `[0, 0, 0]` | 0 | 0だけ |
| `[3, 3, 3]` | 3 | 同じ値で個数が奇数 |
| `[100, -1, -1]` | 98 | 大きい値に小さい値が届かない |
| `[2, 3, 4, 9]` | 0 | 2 + 3 + 4 = 9 で分けられる |
| 20,000個すべて 100 | 0 | 最大サイズ |
