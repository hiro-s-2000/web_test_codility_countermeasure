# Lesson 5 Prefix Sums（公式のlessonの問題）

> Codility公式の [Lesson 5: Prefix Sums](https://app.codility.com/programmers/lessons/5-prefix_sums/) の全問題を、Kotlinで解いた解答です。このLessonの問題は **PassingCars**、**CountDiv**、**GenomicRangeQuery**、**MinAvgTwoSlice** の4問です。
> 問題文は公式ページで読み、下の要約は確認用に使ってください。先に自分で解いてから、答え合わせに解答を開くのがおすすめです。

## PassingCars（Easy）

> 公式の問題文: [PassingCars](https://app.codility.com/programmers/lessons/5-prefix_sums/passing_cars/)

### 問題の要約

- 0 と 1 だけの配列 `A`（長さ `N` は1〜100,000）が渡される。0 は東へ、1 は西へ走る車。
- `P < Q` で `A[P] == 0`、`A[Q] == 1` の組 (P, Q) を「すれ違う車のペア」と呼ぶ。
- ペアの数を返す。ただし 1,000,000,000 を超えたら `-1` を返す。
- ペアは最大で 50,000 × 50,000 = 25億になり、`Int` の上限（約21億）を超える。

| 入力 | 答え | 一言 |
|---|---|---|
| `[0, 1, 0, 1, 1]` | 5 | (0,1) (0,3) (0,4) (2,3) (2,4) |

### 解答コード（O(N)・東行きの数を数えながら進む）

```kotlin
fun solution(A: IntArray): Int {
    var east = 0     // ここまでに見た 0 の数
    var pairs = 0L   // Int だと溢れるので Long
    for (a in A) {
        if (a == 0) {
            east++
        } else {
            // この 1 は、左にある 0 すべてとペアになる
            pairs += east
            if (pairs > 1_000_000_000L) return -1
        }
    }
    return pairs.toInt()
}
```

### 解答コード（別解：累積和で右側の 1 を数える）

```kotlin
fun solution(A: IntArray): Int {
    val n = A.size
    // pre[i] = A[0] から A[i-1] までの 1 の数
    val pre = IntArray(n + 1)
    for (i in 0 until n) pre[i + 1] = pre[i] + A[i]
    var pairs = 0L
    for (i in 0 until n) {
        // 0 の右にある 1 の数を足す
        if (A[i] == 0) pairs += pre[n] - pre[i + 1]
    }
    return if (pairs > 1_000_000_000L) -1 else pairs.toInt()
}
```

### 考え方とポイント

- 左から見て、1 が来るたびに「それまでに見た 0 の数」を足せば全ペアになる。
- 二重ループで全組を調べると O(N²) で、N = 100,000 では間に合わない。
- 別解は Lesson 5 の主題の累積和。「0 の右にある 1 の数」を区間和で求める。考え方は同じで向きが逆なだけ。
- 計算量は時間 O(N)、追加メモリは本命が O(1)、別解が O(N)。

### 試験で間違えやすい点

- 合計を `Int` で持つと、全体の前半が 0、後半が 1 のとき 25億になって溢れ、負の値になる。`Long` で持つか、超えた瞬間に `-1` を返す。
- 条件は「1,000,000,000 を**超えたら**」。ちょうど 10億なら `-1` ではなく 1000000000 を返す（`>=` と書かない）。
- 数えるのは「0 が左、1 が右」の組だけ。1 が左で 0 が右の組は数えない。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| `[0]` | 0 | 最小の N |
| `[1, 0]` | 0 | 逆向きの組は数えない |
| `[0, 1]` | 1 | 最小のペア |
| `[1, 1, 1]` | 0 | 全部同じ値 |
| 0 が 40,000 個、続けて 1 が 25,000 個 | 1000000000 | ちょうど10億は -1 にしない |
| 0 が 40,000 個、続けて 1 が 25,001 個 | -1 | 10億を超えたら -1 |
| 0 が 50,000 個、続けて 1 が 50,000 個 | -1 | 25億でも Int で溢れない |

## CountDiv（Medium）

> 公式の問題文: [CountDiv](https://app.codility.com/programmers/lessons/5-prefix_sums/count_div/)

### 問題の要約

- 整数 `A`, `B`, `K` が渡される。
- `A` 以上 `B` 以下の整数のうち、`K` で割り切れるものがいくつあるかを返す。
- `A`, `B` は 0〜2,000,000,000、`K` は 1〜2,000,000,000。`A ≤ B` は保証される。
- ループで1つずつ数えると最大20億回になるので、O(1) の計算で求める。
- 0 も `K` で割り切れる数として数える。

| 入力 | 答え | 一言 |
|---|---|---|
| A=6, B=11, K=2 | 3 | 6, 8, 10 の3つ |

### 解答コード（O(1)・割り算の差）

```kotlin
fun solution(A: Int, B: Int, K: Int): Int {
    // 0〜B の倍数の数 − 0〜A の倍数の数（A 自身が倍数なら1つ戻す）
    val extra = if (A % K == 0) 1 else 0
    return B / K - A / K + extra
}
```

### 解答コード（別解：最初の倍数から数える）

```kotlin
fun solution(A: Int, B: Int, K: Int): Int {
    // A 以上で最初の K の倍数（Long で溢れを防ぐ）
    val first = (A.toLong() + K - 1) / K * K
    if (first > B) return 0
    return ((B - first) / K + 1).toInt()
}
```

### 考え方とポイント

- 「1〜X にある K の倍数は `X / K` 個」を使い、範囲の数を引き算で出す。
- `B / K` は 1〜B の倍数の数、`A / K` は 1〜A の倍数の数。引くと (A, B] の数になるので、`A` 自身が倍数なら1を足して [A, B] にする。
- 0 は `B / K` にも `A / K` にも入らないが、`A = 0` なら `0 % K == 0` で1足されるので正しく数えられる。
- 別解は「A 以上で最初の倍数」を切り上げで求め、そこから B までに K 刻みで何個あるかを数える。
- 計算量は時間 O(1)、追加メモリ O(1)。

### 試験で間違えやすい点

- `B / K - (A - 1) / K` と書くと、`A = 0` のとき `-1 / K` が Kotlin では 0（0 方向への切り捨て）になり、0 を数え落とす。
- 別解の切り上げ `A + K - 1` は最大で約40億になり Int では溢れる。`toLong()` してから計算する。
- `A` から `B` までループすると最大20億回で性能テストに落ちる。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| A=0, B=0, K=11 | 1 | 0 も倍数として数える |
| A=1, B=1, K=11 | 0 | 倍数が1つもない |
| A=11, B=14, K=2 | 2 | A が倍数でない |
| A=10, B=10, K=5 | 1 | A = B で倍数 |
| A=0, B=2000000000, K=1 | 2000000001 | 最大の答え |
| A=0, B=2000000000, K=2000000000 | 2 | 最大の K（0 と 20億） |
| A=2000000000, B=2000000000, K=1999999999 | 0 | 大きい値で倍数なし |

## GenomicRangeQuery（Medium）

> 公式の問題文: [GenomicRangeQuery](https://app.codility.com/programmers/lessons/5-prefix_sums/genomic_range_query/)

### 問題の要約

- DNAの文字列 `S`（長さ N は 1〜100,000、文字は `A` `C` `G` `T` だけ）が渡される。
- 各文字の重みは `A`=1、`C`=2、`G`=3、`T`=4。
- 質問が M 個（1〜50,000）あり、K 番目は区間 `P[K]`〜`Q[K]`（両端を含む、0 ≤ P[K] ≤ Q[K] ≤ N−1）。
- 各区間に出てくる文字の重みの最小値を、質問の順に `IntArray` で返す。
- 1問ずつ区間をなめると最悪 N×M = 50億回になり、時間切れになる。

| 入力 | 答え | 一言 |
|---|---|---|
| S=`CAGCCTA`, P=[2,5,0], Q=[4,5,6] | [2,4,1] | `GCC`→C、`T`→T、全体→A |

### 解答コード（累積和 O(N+M)）

```kotlin
fun solution(S: String, P: IntArray, Q: IntArray): IntArray {
    val n = S.length
    // cnt[c][i] = 先頭 i 文字の中にある文字 c（0:A 1:C 2:G）の個数
    val cnt = Array(3) { IntArray(n + 1) }
    for (i in 0 until n) {
        for (c in 0 until 3) cnt[c][i + 1] = cnt[c][i]
        when (S[i]) {
            'A' -> cnt[0][i + 1]++
            'C' -> cnt[1][i + 1]++
            'G' -> cnt[2][i + 1]++
        }
    }
    val res = IntArray(P.size)
    for (k in P.indices) {
        val from = P[k]
        val to = Q[k] + 1 // Q[k] を含むので +1
        res[k] = 4 // A, C, G がなければ T
        for (c in 0 until 3) {
            if (cnt[c][to] - cnt[c][from] > 0) {
                res[k] = c + 1
                break
            }
        }
    }
    return res
}
```

### 考え方とポイント

- 文字ごとに「先頭からの出現数」の累積和を作り、区間に A があるか、なければ C があるか…と小さい順に調べる。
- 区間 `[P, Q]` の個数は `cnt[Q+1] - cnt[P]`。1以上なら区間にその文字がある。
- T は最後の候補なので累積和は要らない。A・C・G が1つもなければ答えは4。
- 計算量は時間 O(N+M)、追加メモリ O(N)（3本の累積和）。

### 試験で間違えやすい点

- 区間は両端を含む。`cnt[Q] - cnt[P]` と書くと `Q` の文字を落とし、`P[K]==Q[K]` の質問が全部4になる。
- 累積和の配列は長さ N+1 にする。長さ N で作ると、`Q = N−1` のとき範囲外になる。
- 質問ごとに `S.substring(P, Q+1)` を作って調べる書き方は O(N×M) で、性能テストで時間切れになる。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| S=`A`, P=[0], Q=[0] | [1] | 最小のN |
| S=`T`, P=[0], Q=[0] | [4] | A・C・G がない区間 |
| S=`GT`, P=[0,1], Q=[0,1] | [3,4] | 1文字の区間（両端を含むか） |
| S=`TTA`, P=[0,2], Q=[1,2] | [4,1] | 最後の文字だけの区間 |
| S=`AC`, P=[1,0], Q=[1,1] | [2,1] | 区間の外の A を数えない |
| S=`ACGT`, P=[0,1,2,3], Q=[3,3,3,3] | [1,2,3,4] | 4種類の答えが全部出る |

## MinAvgTwoSlice（Medium）

> 公式の問題文: [MinAvgTwoSlice](https://app.codility.com/programmers/lessons/5-prefix_sums/min_avg_two_slice/)

### 問題の要約

- 整数の配列 `A` が渡される。`N` は 2〜100,000、各要素は -10,000〜10,000。
- 区間 `(P, Q)`（`0 ≤ P < Q < N`）は**要素2個以上**の連続した部分。平均は「区間の合計 ÷ 要素数」。
- 平均が最小になる区間の**開始位置 `P`** を返す（最小値そのものではない）。
- 最小の平均を持つ区間が複数あるときは、一番小さい `P` を返す。

| 入力 | 答え | 一言 |
|---|---|---|
| `[4, 2, 2, 5, 1, 5, 8]` | 1 | (1,2) の平均2が最小。(1,4) は2.5、(3,4) は3 |

### 解答コード（長さ2と3だけを見る O(N)）

```kotlin
fun solution(A: IntArray): Int {
    // 平均が最小の区間は、長さ2か3の区間に必ず現れる
    var bestSum = A[0] + A[1] // 最小平均 = bestSum / bestLen
    var bestLen = 2
    var bestP = 0
    for (p in 0 until A.size - 1) {
        val s2 = A[p] + A[p + 1]
        // s2/2 < bestSum/bestLen を、割り算せず掛け算で比べる
        if (s2 * bestLen < bestSum * 2) {
            bestSum = s2; bestLen = 2; bestP = p
        }
        if (p + 2 < A.size) {
            val s3 = s2 + A[p + 2]
            if (s3 * bestLen < bestSum * 3) {
                bestSum = s3; bestLen = 3; bestP = p
            }
        }
    }
    return bestP
}
```

### 考え方とポイント

- 長さ4以上の区間は、長さ2か3の区間に切り分けられる。全体の平均は部分の平均の間に入るので、どれか1つの部分の平均は全体以下になる。だから長さ2と3だけ調べればよい。
- 同じ最小平均の長い区間が `P` から始まるなら、切り分けた先頭の部分（`P` から始まる）も同じ平均になる。なので「一番小さい `P`」もこの方法で正しく取れる。
- `P` を小さい順に回し、`<`（厳密に小さい時だけ）で更新するので、同点なら先に見つけた小さい `P` が残る。
- 平均は `a/b < c/d` を `a*d < c*b` に直して整数で比べる。値は最大でも 3 × 10,000 × 3 程度なので `Int` で溢れない。
- 計算量は O(N)、追加メモリは O(1)。

### 試験で間違えやすい点

- 長さ2だけを見ると間違える。`[-3, -5, -8, -4, -10]` は長さ2の最小が `(-4-10)/2 = -7`（P=3）だが、長さ3の `(-8-4-10)/3 = -7.33…`（P=2）のほうが小さい。
- `(A[p] + A[p + 1]) / 2` のような `Int` の割り算は小数を切り捨てて順位が狂う。掛け算で比べるか、`Double` にする。
- 返すのは最小の平均ではなく、開始位置 `P`。同点の時に `<=` で更新すると後ろの `P` を返してしまう。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| `[1, 1]` | 0 | 最小の N=2 |
| `[5, 5, 5, 5]` | 0 | 全部同じ値なら一番小さい P |
| `[-3, -5, -8, -4, -10]` | 2 | 長さ3の区間が最小になる |
| `[10, 0, 10, 0, -1]` | 3 | 最後の2要素が最小 |
| `[-10000, -10000, 10000]` | 0 | 負の最大値。長さ2が長さ3に勝つ |
| 10000 が 100,000 個 | 0 | 最大サイズ・最大値 |
