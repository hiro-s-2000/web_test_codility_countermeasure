> 問題文は公式ページで読み、下の要約は確認用に使ってください。先に自分で解いてから、答え合わせに解答を開くのがおすすめです。

## CyclicRotation（Easy）

> 公式の問題文: [CyclicRotation](https://app.codility.com/programmers/lessons/2-arrays/cyclic_rotation/)

### 問題の要約

- 整数の配列 `A` と回数 `K` が渡される。
- 「全要素を右へ1つずらし、末尾の要素を先頭へ回す」操作を `K` 回した配列を返す。
- `N`（配列の長さ）と `K` はどちらも 0〜100。要素は -1,000〜1,000。
- `N = 0`（空配列）もありうる。`K` が `N` より大きいこともある。
- 評価は正しさが中心で、性能はほぼ問われない。

| 入力 | 答え | 一言 |
|---|---|---|
| A = [3, 8, 9, 7, 6], K = 3 | [9, 7, 6, 3, 8] | 基本形 |
| A = [0, 0, 0], K = 1 | [0, 0, 0] | 全部同じ値 |
| A = [1, 2, 3, 4], K = 4 | [1, 2, 3, 4] | K = N で元に戻る |

### 解答コード（行き先を直接計算 O(N)）

```kotlin
fun solution(A: IntArray, K: Int): IntArray {
    val n = A.size
    // 空配列は先に返す（n = 0 で % を使うと 0 除算になる）
    if (n == 0) return A
    val res = IntArray(n)
    for (i in 0 until n) {
        // i 番目の要素は K 個右へ。はみ出したら先頭に回る
        res[(i + K) % n] = A[i]
    }
    return res
}
```

### 考え方とポイント

- 各要素の行き先 `(i + K) % n` を直接計算し、新しい配列に置くだけ。
- `N` 回まわすと元に戻るので、`K` 回は `K % N` 回と同じ。`%` がこれを自動で処理する。
- 1回ずつ `K` 回ずらす素直な方法でも、この問題の上限（100×100）なら間に合う。ただし直接計算のほうが短く、間違いも少ない。
- 計算量は O(N)、追加メモリは結果の配列ぶんの O(N)。

### 試験で間違えやすい点

- 空配列で `K % n` や `(i + K) % n` を計算すると `ArithmeticException`（0 除算）になる。`n == 0` を先に返す。
- 向きを逆にしない。右回転なので、`res[(i + K) % n] = A[i]` と書く。`res[i] = A[(i + K) % n]` は左回転になる。
- `K` が `N` より大きい場合（例: N = 3, K = 100）も `%` で正しく回る。`K - N` を1回引くだけだと 97 のように `N` 以上が残り、添字がはみ出す。`K % N` を使う。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| A = [], K = 5 | [] | 空配列で 0 除算しない |
| A = [], K = 0 | [] | 空配列で K = 0 |
| A = [5], K = 100 | [5] | 要素1つ |
| A = [1, 2, 3], K = 0 | [1, 2, 3] | 回さない |
| A = [1, 2, 3], K = 100 | [3, 1, 2] | K が N より大きい（100 % 3 = 1） |
| A = [-1000, 1000], K = 1 | [1000, -1000] | 負の数と上限値 |
| A = [1, 2, 3, 4, 5], K = 1 | [5, 1, 2, 3, 4] | 1回だけ右へ |

## OddOccurrencesInArray（Easy）

> 公式の問題文: [OddOccurrencesInArray](https://app.codility.com/programmers/lessons/2-arrays/odd_occurrences_in_array/)

### 問題の要約

- 整数の配列 `A` が渡される。長さ `N` は奇数で、1〜1,000,000。
- 要素の値は 1〜1,000,000,000。
- 同じ値どうしで2個ずつ組にすると、1個だけ相手のいない要素が残る。その値を返す。
- 相手のいない値が3回、5回…と出ることもある（そのうち1個だけが余る）。

| A | 答え | 一言 |
|---|---|---|
| `[9, 3, 9, 3, 9, 7, 9]` | 7 | 9は4回、3は2回で組になり、7だけ余る |

### 解答コード（XOR、O(N)）

```kotlin
fun solution(A: IntArray): Int {
    var x = 0
    // 同じ値どうしの XOR は 0 になって消える
    for (a in A) {
        x = x xor a
    }
    return x
}
```

### 解答コード（別解：ソートして2個ずつ比べる、O(N log N)）

```kotlin
fun solution(A: IntArray): Int {
    A.sort()
    // 並べると同じ値が隣り合う。2個ずつ見て、ずれた所が答え
    var i = 0
    while (i < A.size - 1) {
        if (A[i] != A[i + 1]) return A[i]
        i += 2
    }
    return A[A.size - 1]
}
```

### 考え方とポイント

- 全要素を XOR すると、組になった値は打ち消し合い、余った1個だけが残る。
- XOR は順番を入れ替えても結果が同じなので、組の相手がどこにあっても構わない。
- 値が3回出る場合も、2回ぶんが消えて1回ぶんが残るので、そのまま正しい。
- 計算量は時間 O(N)、追加メモリ O(1)。
- 別解は時間 O(N log N)、追加メモリはソートのぶん。Codility では 100% 取れるが、`A` を書き換える。

### 試験で間違えやすい点

- Kotlin では `^` は使えない。XOR は `x xor a` と中置関数で書く。
- `HashMap` で回数を数えても正解だが、100万件だとメモリと時間を多く使う。XOR なら変数1つで済む。
- 別解で、余った要素が最後にある場合（`[1, 1, 2]`）はループを抜けてしまうので、最後の `return A[A.size - 1]` を忘れない。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| `[42]` | 42 | N=1 |
| `[5, 1, 1]` | 5 | 余りが先頭 |
| `[1, 1, 2]` | 2 | 余りが末尾 |
| `[7, 7, 7]` | 7 | 同じ値が3回 |
| `[2, 2, 3, 3, 2]` | 2 | 余る値にも組がある |
| `[1000000000, 1, 1]` | 1000000000 | 最大値 |
