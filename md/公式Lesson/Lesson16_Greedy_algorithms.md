# Lesson 16 Greedy algorithms（公式のlessonの問題）

> Codility公式の [Lesson 16: Greedy algorithms](https://app.codility.com/programmers/lessons/16-greedy_algorithms/) の全問題を、Kotlinで解いた解答です。このLessonの問題は **MaxNonoverlappingSegments**、**TieRopes** の2問です。
> 問題文は公式ページで読み、下の要約は確認用に使ってください。先に自分で解いてから、答え合わせに解答を開くのがおすすめです。

## MaxNonoverlappingSegments（Easy）

> 公式の問題文: [MaxNonoverlappingSegments](https://app.codility.com/programmers/lessons/16-greedy_algorithms/max_nonoverlapping_segments/)

### 問題の要約

- 直線上に N 本の線分がある（N は 0〜30,000）。線分 `I` は `A[I]` から `B[I]` まで（両端を含む）。
- 値は 0〜1,000,000,000 で、`A[I] <= B[I]`。線分は**終点 `B` の小さい順に並んでいる**。
- 共通の点を1つでも持つ2本は「重なる」。端がちょうど接する（`B[i] == A[j]`）のも重なりになる。
- どの2本も重ならないように選べる線分の、最大の本数を返す。N が0なら0。

| A | B | 答え | 一言 |
|---|---|---|---|
| [1, 3, 7, 9, 9] | [5, 6, 8, 9, 10] | 3 | 例えば {0, 2, 3}。4本は選べない |

### 解答コード（貪欲法 O(N)）

```kotlin
fun solution(A: IntArray, B: IntArray): Int {
    var count = 0
    var lastEnd = -1 // 最後に選んだ線分の終点（値は0以上なので-1で「まだなし」）
    for (i in A.indices) {
        // 始点が前の終点より右なら重ならないので選ぶ
        if (A[i] > lastEnd) {
            count++
            lastEnd = B[i]
        }
    }
    return count
}
```

### 考え方とポイント

- 終点が早い線分から順に、重ならないものを取れるだけ取る（区間スケジューリングの貪欲法）。
- 終点が早いものを選ぶほど、右側に残る余地が一番広くなるので、これで最大になる。
- 線分はもう終点順に並んでいるので、並べ替えは要らない。前から1回なめるだけ。
- 判定は「今の始点 `A[i]` が、最後に選んだ終点 `lastEnd` より大きいか」だけでよい。
- 計算量は時間 O(N)、追加メモリ O(1)。

### 試験で間違えやすい点

- 端が接する線分も重なりになる。`A[i] >= lastEnd` と書くと、`A=[1,5], B=[5,6]` で2を返して誤りになる（正しくは1）。
- N=0 がある。`lastEnd = B[0]` で始めて1本目を決め打ちすると、空配列で `ArrayIndexOutOfBoundsException` になる。`-1` から始めれば空でも0を返す。
- 値は最大 1,000,000,000 で Int に収まり、足し算もしないので Long は要らない。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| A=[], B=[] | 0 | 空配列 |
| A=[0], B=[0] | 1 | 長さ0の線分1本 |
| A=[1, 5], B=[5, 6] | 1 | 端が接すると重なる |
| A=[1, 6], B=[5, 6] | 2 | 1離れていれば両方取れる |
| A=[2, 2, 2], B=[2, 2, 2] | 1 | 全部同じ線分 |
| A=[0, 1, 2], B=[10, 10, 10] | 1 | 全部が重なる |
| A=[0, 1000000000], B=[0, 1000000000] | 2 | 最大値の点 |

## TieRopes（Easy）

> 公式の問題文: [TieRopes](https://app.codility.com/programmers/lessons/16-greedy_algorithms/tie_ropes/)

### 問題の要約

- 一列に並んだ `N` 本の縄の長さが配列 `A` で渡される。目標の長さ `K` も渡される。
- 隣どうしの縄だけを結べる。結んだ縄の長さは合計になり、さらに隣と結んでもよい。
- うまく結んで、長さが `K` 以上の縄を最大で何本作れるかを返す。足りない縄は余ってもよい。
- `N` は 1〜100,000、`K` と `A` の各要素は 1〜1,000,000,000。

| K | A | 答え | 一言 |
|---|---|---|---|
| 4 | `[1, 2, 3, 4, 1, 1, 3]` | 3 | 貪欲だと `1+2+3`、`4`、`1+1+3` の3本（公式の説明は `2+3` で先頭の `1` を余らせる結び方） |

### 解答コード（貪欲法 O(N)）

```kotlin
fun solution(K: Int, A: IntArray): Int {
    var count = 0
    var cur = 0L // 今結んでいる途中の縄の長さ
    for (a in A) {
        cur += a
        // K に届いたらすぐ1本として切り離す
        if (cur >= K) {
            count++
            cur = 0L
        }
    }
    return count
}
```

### 考え方とポイント

- 左から縄を足していき、長さが `K` に届いた瞬間に1本完成として数え、0から数え直す。
- 届いたのにさらに結ぶと、その分の縄が次の1本に使えなくなるだけで得をしない。だから「届いたらすぐ切る」が最善になる（貪欲法）。
- 最後に `K` に届かず残った分は、そのまま捨ててよい（数えない）。
- 計算量は時間 O(N)、追加メモリ O(1)。

### 試験で間違えやすい点

- 条件は `K` 以上（`>=`）。ちょうど `K` の縄も1本に数える。`>` にすると公式の例で答えが2になる。
- 途中の長さは「`K` 未満 + 1要素」なので最大 1,999,999,999 で、実は `Int`（最大 2,147,483,647）に収まる。ただし配列全体の合計を `Int` で取ると黙って溢れる（10万本の10億を足すと 276447232 になる）。迷ったら `Long` にしておくのが安全。
- 届かずに残った分を「1本」と数えてはいけない。`K=2, A=[1,1,1,1,1]` の最後の `1` は捨てるので答えは2。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| K=1, A=`[1]` | 1 | 最小の入力 |
| K=10, A=`[1, 2, 3]` | 0 | 全部結んでも届かない |
| K=5, A=`[5, 5, 5]` | 3 | ちょうど `K` も数える |
| K=2, A=`[1, 1, 1, 1, 1]` | 2 | 最後の余りは数えない |
| K=1000000000, A=`[999999999, 1000000000]` | 1 | 途中の長さが大きくなる |
| K=1, A=10万個の `1000000000` | 100000 | 最大サイズ・全部同じ値 |
