## Dominator（Easy）

> 公式の問題文: [Dominator](https://app.codility.com/programmers/lessons/8-leader/dominator/)

### 問題の要約

- 整数の配列 `A`（長さ N は 0〜100,000、各要素は -2,147,483,648〜2,147,483,647）が渡される。
- 配列の半分より多く（N/2 を超える回数）出てくる値を「ドミネーター」と呼ぶ。
- ドミネーターがあれば、その値が入っている位置（インデックス）のどれか1つを返す。どれを返してもよい。
- ドミネーターがなければ -1 を返す。空配列も -1。

| 入力 | 答え | 一言 |
|---|---|---|
| `[3, 4, 3, 2, 3, -1, 3, 3]` | 0, 2, 4, 6, 7 のどれか | 3 が8個中5個で半分を超える |

### 解答コード（O(N)・ボイヤー＝ムーア投票）

```kotlin
fun solution(A: IntArray): Int {
    // 1周目: 違う値どうしを打ち消し合い、候補を1つ残す
    var cand = 0
    var size = 0
    for (x in A) {
        if (size == 0) {
            cand = x
            size = 1
        } else if (x == cand) {
            size++
        } else {
            size--
        }
    }
    // 2周目: 候補が本当に半分を超えるか数え直す
    var count = 0
    var idx = -1
    for (i in A.indices) {
        if (A[i] == cand) {
            count++
            idx = i
        }
    }
    return if (count > A.size / 2) idx else -1
}
```

### 解答コード（別解：HashMapで数える）

```kotlin
fun solution(A: IntArray): Int {
    val cnt = HashMap<Int, Int>()
    for (i in A.indices) {
        val c = (cnt[A[i]] ?: 0) + 1
        cnt[A[i]] = c
        // 半分を超えた時点で、その位置を返せばよい
        if (c > A.size / 2) return i
    }
    return -1
}
```

### 考え方とポイント

- 違う値2つを組にして消していくと、半分を超える値だけは必ず最後まで残る。これを「候補」にする。
- ただし、ドミネーターがなくても何かが候補に残るので、2周目で本当に N/2 を超えるか数え直す。
- 返すのは値ではなくインデックス。どの位置でもよいので、数えながら最後に見つけた位置を返せば済む。
- 計算量は時間 O(N)、追加メモリ O(1)。別解の HashMap 版も時間 O(N) だが、追加メモリは O(N)。

### 試験で間違えやすい点

- 値（`cand`）を返してしまう。答えはその値がある位置のインデックス。
- 2周目の確認を省く。`[1, 2, 3]` でも候補は残るため、確認しないと -1 にならない。
- 「半分を超える」は `count > A.size / 2`。`>=` にすると `[1, 2]` で 1 を誤ってドミネーターにする。
- 空配列は 1周目も2周目も回らず `count = 0 > 0` が偽なので -1 になる。別の分岐は要らない。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| `[]` | -1 | 空配列 |
| `[5]` | 0 | 要素1つは必ずドミネーター |
| `[1, 2]` | -1 | ちょうど半分は足りない |
| `[1, 2, 1]` | 0 か 2 | 半分をちょうど1つ超える |
| `[1, 2, 3]` | -1 | 候補は残るが確認で落ちる |
| `[-2147483648, -2147483648, 2147483647]` | 0 か 1 | Int の最小値・最大値 |
| 100,000個すべて同じ値 | 0〜99999 のどれか | 最大サイズ |

## EquiLeader（Easy）

> 公式の問題文: [EquiLeader](https://app.codility.com/programmers/lessons/8-leader/equi_leader/)

### 問題の要約

- 空でない整数配列 `A`（長さ N は 1〜100,000、各要素は −1,000,000,000〜1,000,000,000）が渡される。
- 「リーダー」とは、配列の要素の半分より多く（過半数）現れる値のこと。
- 位置 `S`（0 ≤ S < N−1）で配列を `A[0..S]` と `A[S+1..N−1]` に分けたとき、両方にリーダーがあり、しかも同じ値なら、`S` を「イコールリーダー」と呼ぶ。
- イコールリーダーになる `S` の個数を返す。

| 入力 | 答え | 一言 |
|---|---|---|
| `[4, 3, 4, 4, 4, 2]` | 2 | S=0 と S=2 で、左右ともリーダーが4 |

### 解答コード（O(N) 投票法＋左右の個数）

```kotlin
fun solution(A: IntArray): Int {
    val n = A.size
    // 投票法で全体のリーダー候補を1つに絞る
    var cand = 0
    var votes = 0
    for (x in A) {
        if (votes == 0) { cand = x; votes = 1 }
        else if (x == cand) votes++
        else votes--
    }
    val total = A.count { it == cand }
    if (total * 2 <= n) return 0  // 全体にリーダーがない
    var left = 0
    var ans = 0
    for (s in 0 until n - 1) {
        if (A[s] == cand) left++
        val right = total - left
        // 左の長さ s+1、右の長さ n-s-1 の両方で過半数か
        if (left * 2 > s + 1 && right * 2 > n - s - 1) ans++
    }
    return ans
}
```

### 考え方とポイント

- 左右で同じリーダーなら、それは必ず全体のリーダーでもある。だから全体のリーダーだけを調べればよい。
- 全体のリーダーは、投票法（違う値どうしを打ち消し合う）で候補を1つ残し、本当に過半数かを数え直して確かめる。
- 左から順に「左側にリーダーが何個あるか」を数え、右側の個数は `total - left` で出す。
- 各 `S` で「左の個数×2 > 左の長さ」かつ「右の個数×2 > 右の長さ」なら数える。
- 計算量は時間 O(N)、追加メモリ O(1)。

### 試験で間違えやすい点

- 過半数は「半分より多い」。`left * 2 > len` と書く。`>=` にするとちょうど半分も数えてしまう。`len / 2` で比べると割り算の切り捨てでずれやすい。
- `S` は `N−2` まで。右側が空になる `S = N−1` は数えないので、ループは `0 until n - 1`。
- 投票法で残った候補は、過半数とは限らない。必ず数え直して確かめる（例: `[1, 2, 3]` は候補3が残るがリーダーではない）。

### 自分で確かめるテストケース

| 入力 | 期待値 | 確かめたいこと |
|---|---|---|
| `[1]` | 0 | N=1 は分け方がない |
| `[5, 5]` | 1 | 最小の分け方 |
| `[1, 2]` | 0 | 全体にリーダーがない |
| `[4, 4, 2, 5, 3, 4, 4, 4]` | 3 | 左側でちょうど半分になる位置を数えない |
| `[0, 0, 0, 0, 0]` | 4 | 全部同じなら N−1 個 |
| `[-1000000000, -1000000000, 1000000000]` | 0 | 負の数と端の値、右側に過半数がない |
